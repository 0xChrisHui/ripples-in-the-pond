# P16-E — 铸造界面、资产页面与恢复体验

> 目标：让用户清楚知道自己在哪条链、谁付 Gas、交易进行到哪，并能在离开页面后恢复。\
> 前置：P16-D 完成。\
> 状态：旧快照保留产品行为；界面必须重新适配 `main@f24f5bd` 的 P11 路由事务与 `/me` 档案结构。\
> 完成后进入：P16-F。

## 1. 链选择组件

P11 集成红线：P16 只在现有 `/me` 档案内增加网络选择与铸造弹窗，不接管 Persistent Pond、Score 路由事务、曲谱预热或播放器生命周期。动共享文件前只做相关接口的定向 review；不把 P11 的完整压力矩阵并入 P16。

组件只在以下条件同时满足时显示：

- 当前动作是铸造 ScoreNFT；
- 服务端 capability 允许选择链；
- 当前存在已认证的外部钱包；
- ETH 功能开关对该用户启用。

两个选项：

- `OP — 平台支付 Gas`，默认选中；
- `Ethereum — 你用钱包支付 Gas`，附实时估算和余额提示。

切换选项只改变本次订单意图，不立即请求钱包切链。离开并重新打开铸造确认页时默认回到 OP，除非有一张已存在的 ETH 活跃订单需要恢复。

ETH 使用两层确认：第一层只做钱包、网络、余额和保守 Gas 预检；用户点击“准备永久作品”后才占用作品、预留 Token ID 并上传不可变素材。第二层由 Privy/钱包展示真实 `redeem` 交易。这样不自建钱包弹窗，也尽量减少用户还未理解费用就产生孤儿 Arweave 资源。

## 2. ETH 确认界面

最终确认前必须同时展示：

- 网络：Ethereum Mainnet 或 Sepolia；
- 当前付款钱包的缩略地址与 connector；
- NFT 接收地址；
- 预检阶段显示保守 Gas 范围；voucher 就绪后显示 viem 精确估算与当前 ETH 余额；
- “铸造价格为 0，但钱包会支付网络 Gas”；
- 素材与 metadata 已上传后不可删除的提示；
- ScoreNFT 合约地址或区块浏览器入口；
- 明确的取消按钮，取消不切链、不发交易。

钱包账号变化、估算过期或链配置变化时，确认按钮立即失效并重新校验。最终确认 UI 使用 Privy + 外部钱包原生界面，站内不重复伪造一套交易确认 modal。

## 3. 过程状态

用户可见文案与内部状态一一对应：

| 内部状态 | 用户文案重点 |
|---|---|
| `preparing_assets` | 正在准备并永久保存作品 |
| `ready_to_sign` | 等待钱包确认，不代表已经扣 Gas |
| `submitted` | 交易已提交，给出浏览器链接 |
| `confirming` | 链上已看到交易，等待确认 |
| `success` | 铸造完成，进入规范资产页 |
| `expired` | 授权已过期，可重新生成，不必重传素材 |
| `failed` | 解释确定失败原因和安全重试方式 |
| `manual_review` | 不要重复发送，系统正在核对 |

不得使用一个无限 loading 覆盖全部阶段，也不得在拿到 txHash 时提前显示“铸造成功”。

## 4. 页面关闭后的恢复

- `/me` 或当前作品页显示活跃 ETH 铸造订单；
- 用户重新登录后按应用用户 ID 查询订单，再校验当前钱包地址；
- 有 txHash 时优先展示交易状态，不要求用户再次签名；
- `ready_to_sign` 且地址一致时可以继续；
- 地址不一致时只允许查看，不允许继续签名；
- `manual_review` 隐藏重试按钮，防止重复支付 Gas；
- 已预留但未铸造的 Token ID 明确显示为“未铸造编号”，不得生成 NFT 资产页；
- 成功订单自动链接到完整多链资产页。

## 5. 多链 Score 页面

规范页面读取完整 `chainId + contract + tokenId`，并展示：

- 链徽标与网络名称；
- NFT 合约、Token ID、owner；
- 音频、封面和 metadata；
- 对应区块浏览器链接；
- 铸造交易和完成时间；
- ETH 资产不展示 Pond Echo 入口或 OP 专属状态。

旧 OP 短路由继续工作，并可设置规范 URL 指向完整路由；分享卡与 OG 不能只用 Token ID 作为缓存键。

## 6. 运营与诊断

内部诊断至少可按以下字段查询：

- orderId、预留 tokenId、用户、recipient、chainId；
- 状态、txHash、tokenId；
- 素材 URI 与内容哈希；
- 凭证摘要和 deadline；
- 最近对账时间与稳定错误码。

关键指标：

- 钱包连接成功率、SIWE 成功率；
- MetaMask 与 WalletConnect 分入口失败率；
- 选择 ETH 的比例；
- prepare 到签名、签名到广播、广播到成功的转化；
- 用户拒签、余额不足、过期和 manual review 数量；
- 平均确认时间与 RPC 错误率；
- 已上传但未完成铸造的永久素材数量。

日志和分析不采集助记词、私钥、完整签名或与排障无关的个人信息。

## 7. 可访问性与移动端

- 链选择使用可键盘操作的 radio 语义；
- 状态变化通过合适的 live region 通知，不连续刷屏；
- 地址与费用不只靠颜色区分；
- WalletConnect 二维码在窄屏不作为唯一方式；
- 从 imToken 返回浏览器后能恢复原确认页；
- 长地址、长交易哈希和错误信息不撑破移动布局；
- `prefers-reduced-motion` 下不依赖动画表达交易状态。
