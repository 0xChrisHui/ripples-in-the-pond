# Phase 18 — 曲目铸造体验收口（/tracks 领取区、收藏联动、/me 铸造记录、花瓣层级）

> 制定日期：2026-10-09。状态：执行计划，尚未开发。\
> 基线：`main@7c64650`（P17 已上线；/tracks 领取区重构与拒签版本冲突修复已在其中）。\
> 本计划只改产品体验与读取侧汇总，**不改合约、不改数据库表结构、不新增依赖**。

---

## 1. 用户可验收的结果

1. 只有用外部链上钱包登录的用户，`/tracks` 的“收藏原曲”里才出现 Ethereum；邮箱/SEMI/手机号登录只见 Optimism；未登录只见一个“登录后收藏”入口。
2. ETH 一步铸造：点“铸造 Ethereum 原曲”后直接建单、授权并弹出钱包签名，不再有“领取”与“在钱包中确认领取”两步。全站“领取”统一改称“铸造”（含 Optimism 按钮）。
3. 链卡标题处的“✓ 凭证已核验”删除；“尚未部署”等其他状态保留。
4. 进入 `/tracks` 或切换曲目后，两个铸造按钮立即可点；初始化未完成时点击会显示“正在准备钱包…”，就绪后自动继续。
5. `/` 的爱心收藏与 `/tracks` 的 OP/ETH 铸造，**都会在 `/me` 的收藏中新增记录**。同一首可重复收藏、互不冲突、不弹警告。
6. 在 `/` 收藏或在 `/tracks` 铸造提交后，右上角出现“你的收藏已记录，到「我的」查看”，带跳转；提交即弹，不等链上确认。
7. `/me` 往下翻有“铸造记录”列表：唱片（Score）与原曲，按时间倒序；每条含曲目名、链、类型、状态、时间与区块浏览器链接；成功与进行中都显示。
8. `/` 首页：音乐圆圈在水下时花瓣在其上；圆圈在水面层以上时花瓣在其下，重叠处被圆圈遮盖。

## 2. 已核对的事实

| 事实 | 位置 | 对实施的约束 |
|---|---|---|
| `/` 收藏**会产生链上行为**，只是异步：写 `mint_queue` pending，cron 用平台运营钱包在 **OP 旧 MaterialNFT** 上铸造，Gas 平台付 | `src/hooks/useFavorite.ts`、`app/api/mint/material/route.ts` | 提示文案不能写“已上链”；只说“已记录” |
| 旧路径有自己的重复检查：同用户同 `tokenId` 已有 `mint_events` → 409 | 同上 | 这只作用于旧合约；不要把它扩到新合约 |
| `/tracks` 的 OP 用**新 SBT 合约**，经 `api/material-mint/op`；ETH 用新订单表 + 钱包签名 | `src/lib/material-mint/server/op/service.ts`、`app/api/material-mint/*` | 两条链路合约不同，同一首可并存；`/me` 须区分来源，不得去重 |
| ETH 铸造流程：prepare → authorization → attempt → 钱包发送 → submission | `src/features/material-catalog/mint/order-client.ts` | 一步化只合并**界面步骤**，状态机与恢复机制不动 |
| 拒签/登记 hash 遇版本冲突已会重读重试 | `order-client.ts:transition` | 一步化必须沿用，不得绕过 |
| 领取区组件在 `src/components/music-catalog/claim/` | — | 目录文件数已接近 8 上限，新增须先规划子目录 |

## 3. 待核对点（开工前先查，不得凭猜测改）

- **N1（第 4 项）**：为何进页面/切曲目后按钮禁用数秒。怀疑 `MaterialMintPanel` 的 `scope`（含 `authSource/userId/evmAddress/trackId`）每次切曲目重建子树，`OpMaterialMint` 重新请求 `op/status` 且在 `!status?.recipientAddress` 时禁用按钮；ETH 侧 `auth.ready`/外部钱包尚未就绪。先用日志确认，再定修法。
- **N2（第 5/7 项）**：`/me` 的收藏现在读哪些表（`mint_events`、`mint_queue`、`material_mint_orders`），Score 的铸造记录读哪张表，字段能否直接合并。
- **N3（第 8 项）**：圆圈所在层的变量名、水面层常量名及取值语义（数值大小与“上/下”的对应）。对应关系不清时，先回来问用户，不自行假设。
- **N4（第 6 项）**：音乐合奏成功的“你的创作已记录”提示组件位置，能否直接复用。

## 4. 分组与步骤

### A — /tracks 领取区（改动集中在 `claim/`）

| 步 | 内容 | 验收 |
|---|---|---|
| A1 | 按身份决定展示：外部钱包→OP+ETH；其他已登录→仅 OP；未登录→单个“登录后收藏” | 三类身份各一次读代码级走查 + tsc |
| A2 | ETH 一步铸造：点击→必要时等待钱包就绪→prepare→发送；拒签复原按钮并提示“已取消，可再次点击”；文案“领取”→“铸造” | 保留订单与恢复；`scripts/p17/pipeline/verify-client.ts` 仍通过 |
| A3 | 删除“✓ 凭证已核验”徽标 | 仅该字样消失 |
| A4 | 按 N1 结论修复：按钮始终可点，点击时等待初始化并自动继续，超时给出提示 | 切曲目不再禁用；等待态文案可见 |

### B — 铸造反馈与 /me 联动

| 步 | 内容 | 验收 |

| B2 | 确认 `/` 收藏与 `/tracks` 铸造都能进入 `/me` 收藏（见 C1 的读取合并）；两边互不拦截 | 同曲两边各铸一次均不报冲突 |

### C — /me

## 5. 红线

- 不改合约、不新增 migration、不新增依赖；读取侧合并优先。
- 不改写订单状态机与对账 cron；一步化只改界面编排。
- 任何生产库写入、链上交易须先告知用户并取得同意。
- 不碰工作区中与本计划无关的未提交/未跟踪文件（第 36 圆、`public/the36/`、`contracts/.gas-snapshot` 等）。
- D 项不自行运行 GL；交付时写明“去哪个页面看什么”。

## 6. 验证与复审

- 每组：`tsc --noEmit`、受影响文件 ESLint、既有定向脚本（A2 须跑 `verify-client.ts`）。
- 真实钱包铸造、`/me` 列表真实数据、GL 观感：由用户点验，我不冒称已验。
- A2、C1、C2 完成后，建议让 Opus 5.5 做一次独立复审，聚焦一步化流程与 `/me` 汇总的边界情况。
