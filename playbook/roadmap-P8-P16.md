## Phase 8：水塘视觉重设计

**目标：把首页从"星空视觉"改成"水塘视觉"。**

主要做：

- 首页视觉语言从星空 / 宇宙感，转向水塘 / 涟漪 / 水面感
- 小球仍先保持现有数量，不在本 Phase 改成 35
- 优先解决产品气质问题：
  - 更像 Ripples in the Pond
  - 更有水面、涟漪、池塘、漂浮感
  - 弱化星球 / 宇宙 / 星系感
- 先把首页主视觉调对
- **P8-L（水塘生命感深化）**：新上 20 首音乐（L1）/ 小球运动轨迹+滚轮无序扰动（L2）/ 边缘虚化+曲线细胞感（L3）/ 涟漪遇小球分散漂游（L4）

## Phase 14：钱包配方音乐 NFT 自动空投

**目标：把钱包第一次铸造 ScoreNFT 的行为，转化为一枚终身唯一、可转让、可永久重演的配方音乐 NFT。**

主要做：

- 以 OP Mainnet 钱包地址作为确定性随机种子
- 从 `A-Z + 0-9` 共 36 个约 7 秒碎片中生成固定 36 位配方
- 允许碎片重复或缺失，总播放时长约 4 分钟
- NFT 永久保存配方及实际用到碎片的直接 Arweave 地址，不合成新 MP3
- 仅当钱包历史上第一次成功铸造 ScoreNFT 且事件发生在 P14 启用后时触发
- 每个钱包终身最多一枚；NFT 可转让，转让不恢复原钱包资格
- 系统承担 gas 并异步空投，不阻塞 ScoreNFT 铸造主流程
- 首页增加持有人入口和配方播放器
- 不扫描、不补发 P14 启用前的历史钱包

**v2 决策（2026-09-05）**：旧“手动混音界面 + 选择音轨 + 合成 MP3 + 主动铸造 RemixNFT”方案整体作废。完整规格、Track、异常矩阵与 Gate 见 `playbook/phase-14/00-overview.md`。

## Phase 15：全站丝滑体验与永久播放可靠性

**目标：让核心页面快速响应、真实内容渐进出现，并同时保证 NFT 高速播放与脱离本站后的永久复现。**

主要做：

- 建立 `/`、`/me`、`/score/[id]`、`/artist` 和 P14 页面的冷/热性能基线
- 点击立即反馈，所有核心路由提供稳定、非空的页面外壳
- 首页优先显示水塘和第一批真实音乐圆圈，再渐进启动 WebGL、音频预热和次要效果
- `/me` 解耦身份恢复、三段档案读取和本地草稿上传，减少整页等待
- 公共数据与私人档案采用边界清楚的真实缓存和后台刷新
- NFT 播放采用高速镜像优先、Arweave 双网关 fallback，永久 manifest 保持唯一真相
- 区分首次加载慢与播放中掉帧，分别处理网络、解码、主线程和 WebGL 瓶颈
- 完成移动端、慢网、换号、坏缓存、网关故障与本站关闭模拟

**立项决策（2026-09-05）**：P15 完整取代原“音效系统扩展”。旧音效扩展不自动并入 P16，退回未排期清单；完整规格见 `playbook/phase-15/00-overview.md`。
