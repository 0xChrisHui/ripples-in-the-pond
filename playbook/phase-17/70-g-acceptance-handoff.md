## 1. 单一交接位置与状态

本线lane固定`p17`：

- 按需附件：`reviews/evidence/parallel-2026-10/<runId>/p17/`，即前文 `P17_EVIDENCE`；普通 baseline/verification/*-gate/report 文件名一律视为 handoff 段落，不要求独立建文件。较大日志或机器输入才附文件；交易/永久上传账本与必要安全证明仍独立保留。

## P17-G0：覆盖需求的证据核对

**输入依赖**：A–F 各 Step 结果，包括明确 pending/not_needed；总控 BASE 和允许依赖提交。证据按相关源码、依赖/配置、目标数据与环境复用，SHA 仅追溯；无关提交或纯合并不使证明失效，不为 G 收口重跑已通过层。

**实际文件/符号**：本线代码、唯一 handoff 与按需证据，C1/C2 的 registry/生成数据。优先用现有鉴权、钱包发送和验证基础；各 Track 脚本名仅是能力缺口的建议位置，不为报表、预定文件清单或验收再造工具/大重构。

**具体操作**：逐行填写结果、证据链接和未完成原因：

| 目标 | 最低证明 | 未达标时的准确状态 |
|---|---|---|
| 35首真实曲目 | 35个稳定既有trackId与音频/编号对应；无36/Echo混入 | 数据缺失项明确，不用mock补齐 |
| C1可消费 | schema/validator/接口可运行，真实完整SHA+revision，P13可定位提交 | C1 pending，P13可做其他本地对接工作 |
| 唯一清单 | 页面投影与P13导出同revision，地址集合双向一致 | integration pending，不宣称对接完成 |
| 旧OP兼容 | 合约/冻结URI未改、旧收藏及旧Score链接仍正常 | 阻断相关新发布，不回滚旧NFT |
| ETH安全 | EIP712/权限/重放/URI/正确recipient/receiver回滚、事务与真实对账证明；发行政策相关断言仅在明确确认后实施 | 只挂起待决政策/受影响生产能力，其余通用安全工作继续 |
| 目录页面 | 35首可选，真实手记/链凭证状态、无自动播放/焦点跳动；缺collection附加metadata不阻断既有音频/目录 | 未部署或附加资料pending单列，不冒充已齐备也不扩大阻断 |
| 单曲公开播放 | 真实坐标页面能听对应音频，无伪Score字段、无需登录 | 网关暂失败与代码失败分别记录 |
| 收藏能力 | OP/ETH登录矩阵，真实接收地址、状态准确、未知不重复发送 | 用户签名或外部部署pending |
| 共享体验 | 首页曲目入口、Score/Echo/原曲互斥、平滑退场、seek保留 | 总控接线pending |
| 70项留存 | P17维护的35×2逐项真实证明、指定余额>=1、unknown=0，P13默认复用 | 报实际OP/ETH计数，不以交易数代替，不多线重验 |
| SEMI支持 | P13实际钱包/资源类型验收回执 | 只交对接包，external_pending |

**失败恢复**：只修本线新改动或必要接口；范围外历史债务登记而不扩张。无法安全修的项保留证据，继续独立完成项。

**定向验证**：对照下节只补缺失/失效断言；相关源码/依赖/环境未变就复用，不以整个 commit 是否变化判断。不同网络的链状态不可替代，但两链引用同一永久资源可共用媒体证明；余额/权限的新鲜度按实际操作风险核对。

**完成证据**：handoff 的验收段落记录每项 pass/fail/pending、相关源码/依赖/环境和证明引用；不强制另建 acceptance.md，不复制已有安全日志。

**自动下一步**：G1。

## 2. 验证清单与调用时机

下列命令是能力示例：先用已有等效检查，仅确有缺口时最小补齐，不强制为清单新建脚本。本轮文档不执行代码验证。普通 Step 不跑全仓 verify/全量构建，执行成功即停止该检查，不顺带修无关失败。

| 检查 | 命令/方式 | 何时执行 |
|---|---|---|
| 目录schema、revision、真实35曲 | `npx tsx scripts/p17/catalog/verify.ts` | A2及目录语义变化后 |
| TS/Solidity签名向量 | `npx tsx scripts/p17/contracts/verify-voucher.ts` | C02，typed data变化后 |
| 合约专项 | 既有对应测试或 `forge test --root contracts --match-path 'test/p17/*.t.sol'` | C03；仅受影响合约/继承依赖变化后补测，旧Material/Score不默认全回归 |
| 真实订单恢复 | 既有恢复/事务入口；确需新增才用 verify-local-flow/verify-recovery | D0/D4产生证明，F1/G复用；仅补缺失串联断言 |
| 链接/资产投影 | `npx tsx scripts/p17/catalog/verify-surface-links.ts` | E4/C2 |
| 静态代码 | 项目现有类型检查；eslint仅受影响文件，不另搭检查框架 | 按相关源码/依赖变化检查，交付/合并不自动重跑 |
| 页内排版/音频/焦点/退场 | K2一次必要且有明确断言的浏览器Gate | 静态/定向测试无法回答时才执行，lane不另跑完整矩阵；失败只补测受影响项 |
| 真实mint/迁移/永久上传 | 对应F/B/D Gate | 只在外部动作获授权后 |
| production build | 仅路由/打包/部署风险需要时，由总控K2集中一次 | 无风险不跑；普通Step/worker不build，不默认全仓verify |

浏览器 Gate 确有必要时交 K2 最终集成位，复用现有会话，不复制 profile、不新建发布/验证 worktree。只选与本次改动直接相关的断言：必要代表宽度、网络文案位置、目录选择、手动播放/切曲/结束/seek、首页焦点和音频互斥；已有有效证据直接复用，不重开全设备矩阵或逐曲听完 35 首。

合约/数据库属于高风险，即使夜间UI已可看，也不能省略重放、鉴权、事务和未知结果恢复Gate。缺环境时记录未执行，不伪造成通过。

资产链/媒体证明统一由 P17 维护，A/B/F 共用索引；P13 只核对同 revision 导出集合及钱包特有兼容性，不重新读链/下载全部 70 项。新增不可变上传仍须权利/授权与账本；不能借精简删除 recipient、权限、防重放、事务、unknown 安全证明。

## P17-G1：交付已验证提交和精确接线请求

**输入依赖**：G0；P17工作树中没有他线写入，C1/C2完成提交有明确边界。

**实际文件/符号**：只写P17 HANDOFF和证据；`git diff`、`git status`只读核对；提交只发生在未来已授权独立执行阶段，当前文档不commit。

**具体操作**：

1. `git diff --check`与显式改动路径检查；每个提交只收P17文件，中文说明，禁止`git add .`或收进别人预存改动。共享文件变更先由总控/负责人完成。
2. C1独立基础commit、C2数据commit、后续UI/业务commit均列完整SHA及dependsOn。P13消费总控指定的真实提交，不拷贝工作树中未提交数据。
3. handoff逐项填：lane、BASE_SHA、headSha、dependsOn、completedSteps、nextStep、status、修改路径、各步骤结果/验证引用、相关源码与依赖/环境、C1/C2 SHA+revision、公共接线、外部pending、非显然决定；不要再为每 Step 创建同内容报告。
4. integration request给出文件/符号、当前接口、需要的输入/输出、原因、调用方和验收断言。列header、`/score`根入口、PlayerProvider、GL视觉适配、chain registry、middleware、env/cron、migration实际号。
5. 包含原曲完整性策略、ETH 发行政策的明确确认依据或 pending、OP 原有每用户一次兼容、手记网站后补等决定，交总控归并 JOURNAL；不把“ETH 终身一次”或无限发行写成默认，不自行修改公共文档。
6. 把运行入口、启动命令、端口、需要的非秘密环境项和停止方式交总控；默认只启动获分配的本地服务，不代替总控发布生产。

**失败恢复**：工作树出现外来dirty先保留，不能stash/覆盖/强行提交；只提交可明确归属的本线路径。若提交hook失败，只修本次范围，保留未提交证据给总控，不能跳过hook。

**定向验证**：`git show --stat <完整SHA>`可复核路径归属；无密钥/原始私人数据；引用的证据确实存在，未来尚未生成的证据明确标pending。

**完成证据**：唯一`p17-handoff.md`，完整本地HEAD、C1/C2、实际证据链接。不能留占位SHA并声称移交。

**自动下一步**：将本线交总控K2；总控有具体本线集成回修请求时执行G2，否则进入最终交付。

## P17-G2：集成回修与最终结果

**输入依赖**：总控K2合并SHA/接线结果与明确P17回修项；无请求不自行改其他线。

**实际文件/符号**：限定P17所属文件；共享文件仍总控单写。P13一致性脚本/清单只读使用。

**具体操作**：

1. 只修由集成暴露的P17接口差异；根据最终共享host/视觉签名适配调用，不把P15新退场实现改回旧实现。
2. 目录数据若变化，更新revision/生成文件并交新C2或后续同合同数据commit；P13重生成后才比对最终页面和清单。
3. 只重跑受影响验证；合约/type/媒体证明按相关源码、依赖/配置、目标数据与环境复用，合并后 SHA 改变本身不是重跑原因。构建只有路由/打包/部署风险触发 K2 一次，必要视觉验收也集中 K2；无关项不补跑。
4. 更新handoff：可直接本地查看的需求、总控仍需接线的项、OP/ETH实际留存计数、SEMI外部进度、缺稿/签名/费用输入。
5. 保存工作树与证据，不擅自push、部署、联系SEMI团队或清理用户原脏目录。

**失败恢复**：无法安全解决的跨线接口冲突交总控按所有权裁决；保留原提交和具体失败证据，继续独立验收项。主网已确认资产不可回滚，不用补发“修复”历史证明。

**定向验证**：最终页面/导出坐标等式仅在有关目录/投影/接口变化时补测；其余 P17 回归按实际影响执行，不因最终集成 SHA 新增而全跑；不重复浏览器或 70 项资产矩阵。

**完成证据**：更新唯一 handoff 的验收段落，区分 `code_ready`、`integration_ready` 与 `external_pending`；如外部项未完成，顶层可标 external_pending 并保留本地代码完成字段，不额外生成另一份 acceptance。

**自动下一步**：授权范围已完成则停止，等待用户晨间验收；真实外部项从已记录的F2/F3或P13步骤恢复，不从P17-A0重做所有成功工作。

## 3. 给用户的晨间摘要

汇总只需：

- 本地入口、最终集成SHA与35曲目录是否可用。
- 单曲播放、收藏与共享接线的实际完成状态。
- C1/C2完整SHA和revision，是否已交P13。
- OP留存`实际数/35`、ETH留存`实际数/35`、unknown数量；不用“70笔交易成功”替代。
- SEMI已交资料还是实际已支持播放；用户手记尚缺则直说。
- 需要用户处理的不可替代事项：真实接收地址、费用上限、钱包签名或外部接入权限。

凡没有真实证据的项目都不能计入完成。文档撰写完成、本地实现完成、生产留存完成、SEMI正式支持是四个不同结果。
