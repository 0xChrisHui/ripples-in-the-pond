# P13-W — SEMI 播放协议、实际验收与完成等级

> 前置入口：[P13 总览](00-overview.md)、[R 轨交接](10-registry-handoff.md)。遵循[总控](../parallel-2026-10/00-orchestration.md)、[共享合同](../parallel-2026-10/10-shared-contracts.md)和[汇总验收](../parallel-2026-10/30-acceptance.md)。
> 本线负责把真实资产接入资料和可验证的播放要求交付出去。SEMI 仓库、接口、账号和当前发布版本未经确认时，不修改 reference 快照来冒充合作方已上线。

交接和验证结果统一写入 `reviews/evidence/parallel-2026-10/<runId>/p13-handoff.md`（下称 `P13_HANDOFF`）；必要附件才放同 runId 的 `p13/`（下称 `P13_EVIDENCE`）。优先引用 P17/现有证据，不要求每步单独报告。本次编写计划不生成实施证据。

## 1. 媒体与播放能力表

| 类型 | 永久来源 | 推荐 SEMI 处理 | 不能作出的假设 |
|---|---|---|---|
| Material / 直接音频原曲 | metadata 的 `animation_url` 指向 `ar://` MP3；以实际 metadata 为准 | 钱包原生 audio 播放，可提供暂停、进度及浏览器确实支持的 seek；网页原曲播放地址为在线补充入口 | 不当 HTML iframe，不发送 Score 消息，不改已冻结 URI |
| 原 Score / ETH Score | NFT 的 `tokenURI → metadata.animation_url`，钉住 HTML 与 `events/base/sounds` | 隔离的 HTML 播放容器；仅对实证支持的 Decoder 启用 v1 消息控制 | 不用本地最新版 Decoder 替代历史对象，不推断 v1 支持外部 seek |
| Pond Echo | `tokenURI → animation_url`，携带 `v/recipe/clips` | 隔离 HTML 容器内原生控件；消息能力需逐永久版本证明 | origin 钱包不等于当前持有人，Echo HTML 不自动具备 Score v1 |
| 未知/不支持的 media | 保留实际 URI 与错误原因 | 明确不可内播及永久打开入口，提出适配任务 | 只显示封面、外跳官网或按钮无响应不能算钱包内播放完成 |

如 SEMI 当前只接 HTML，原曲直接音频的解决方向是合作方支持 audio MIME 分流，或在合作方自身容器中包装原生 audio。由 SEMI 确认可用实现并验收；P13 不修改已冻结 metadata，不新上传一个“替代永久版本”掩盖兼容问题。

## W0 — 形成逐媒体类型的接入协议

**输入依赖**：P13-R1 的源码核对；C1/P13-R3 到达后补入真实媒体与 Decoder 版本。可在等待 C1 时先完成通用协议文字。

**实际文件/符号**：只读 `src/score-decoder/index.html` 的 `emit/emitState` 与 message 监听器、`src/wallet-recipe-decoder/index.html` 的 `params/load/play/stopSources`；`scripts/arweave/material/upload-metadata.ts:metadataBuffer`；协议说明并入 `docs/integrations/semi/README.md`，不另建协议文档。

**具体操作**：

1. 每种资产按 P13-R3 复用或补查的有效证据列 `mediaKind`、原始 URI、HTTP 解析方式、controls 和永久版本证据。相同 URI/hash 版本的能力说明复用一次，不逐 Token 重写。能力字段不反写 P17 registry 或改变 catalog revision。
2. Score v1 复用 [P10-F D-F1](../phase-10/70-f-decoder-postmessage.md)：父页命令 `{source:'ripples-parent',type:'play'|'pause'|'toggle'}`；Decoder 事件 `{source:'ripples-decoder',v:1,type:...}`。
3. 逐项抄核实际公共字段：`ready.durationMs`；`state.playing/positionMs/durationMs`；`ended`；`error.message`。只把经过永久版本验证的能力列为 supported，未验证明确 unknown。消息中的位置/时长按 ms 处理，不能混成秒。
4. 父页等 ready 后才允许发送命令；状态由 Decoder 的 state 事件更新。首播必须有用户手势，浏览器阻止时展示可操作的 iframe 内播放按钮或错误，不循环 autoplay。
5. 父页接收消息须比对 `event.source===iframe.contentWindow`、source/type/v、有限数值与字段形状。非 opaque origin 再校验实际网关 origin；sandbox 导致 `origin='null'` 时凭绑定窗口/会话分流，不全局接受任意 null-origin 消息。旧帧卸载后事件不能控制新曲。
6. 沿用最小 sandbox（例如 `allow-scripts`）并按实测决定 autoplay 委托；不默认开放同源、弹窗、顶层跳转。永久网关发生跳转时记录最终 origin 并纳入允许策略，不能为过测试关闭所有限制。
7. v1 无外部 seek/音量协议；它内部已有拖动条也不改变这一事实。父页进度可只读，不能显示可拖动但无效的控件。没有消息桥的 Echo 仍可容器内播放；不宣称全局迷你条已可控。
8. 详情页关闭与迷你条关闭分开约定：前者若要继续播放，必须保留同一个播放器实例并实际验证；后者暂停并销毁媒体/iframe。切换曲目先停旧曲，避免双声。能力不足时停止并如实显示，不假装持续播放。
9. 原曲钱包内播放不要求登录项目站点；当前持有来自链/可信索引，播放资料来自公开 metadata。不得把 SEMI JWT、私钥或手机号送进 iframe、分享 URL 或导出包。

**失败恢复**：永久版本没有协议或 MIME 不兼容，记录逐资产适配缺口；提供当前真实可用的永久打开方式。由总控转给负责方，P13 不越权改 Decoder 或公共 PlayerProvider。

**定向验证**：协议字段对照本地与实际永久 Decoder 证据；已有源码只证明候选能力。链接/静态字段检查；不因写协议启动浏览器。

**完成证据**：README 中的媒体能力说明、永久版本/URI 引用；handoff 记录 unsupported/unknown 项和最小适配请求。

**自动下一步**：W1；C1 尚未到时只整理现有说明，等真实输入后选取断言，不为等待预建验收工具。

## W1 — 复用播放证据，必要时用现有入口小样本验收

**输入依赖**：P13-R2/R3、W0、已有播放证据或现有播放入口/永久 Decoder。需要实测时选真实可读资产，不用 demo 模式或假音频替代。无需独立端口；满足 W2 条件时直接在 SEMI 验收，不先跑一遍本地流程。

**实际文件/符号**：`docs/integrations/semi/assets.ready.json`、P17/现有播放证据、现有单曲/Score/Echo 播放入口及 NFT 实际钉住的永久 Decoder。P13 不新建 `playback-check.html`、本地 HTTP 服务、消息测试平台或业务页面。

**具体操作**：

1. 从同 revision 的机器表选坐标/真实媒体，不手写另一份地址。先引用 P17/已有身份、URI、格式和播放结果，按资源 URI/hash、播放器/Decoder 版本及相关环境判断是否仍有效；无关 commit 或 revision 变化不触发重新试听。
2. 在 handoff 简记本次受影响的断言、复用依据和缺项。只新增导出说明且媒体/播放路径没变时，不默认开启浏览器。SEMI 环境、账号和授权齐备时直接 W2，钱包实测同时覆盖所需播放断言，不重复本地验收。
3. 缺少有效播放证据时，用现有入口或永久 Decoder 对受影响的媒体类型/版本各选一枚代表，确认实际出声及本次相关控制；相同资源跨链复用音频证据，链身份独立核对。仅修改入口/映射不要求重听全曲；结束/连续性受影响才检查相应片段或必要完整播放，不默认逐版本全套或 35 首试听。
4. 35 首映射和 70 项留存仍由 P13-R2/R3 的本地一致性检查覆盖；小样本只减少交互重复，不替代完整地址/结果核对。现有入口无法证明的能力标 unknown/待验，不为补齐断言先建测试平台。
5. 断站与网关回退优先复用相同 URI/hash、Decoder 版本及相关配置的 P17/既有证据。只有引用/回退逻辑变化、缺证据或冲突才定向测试：使用现有入口，按需要阻断自有站点/API/CDN 或相关网关，不扩大到全站演练。能力不足如实记录，不替换已钉住的 Decoder、不自动重传。
6. 必须站内实测的项合入总控 K2 的一次必要验收，复用现有浏览器会话，不在线内先跑一遍再交总控重跑；实际 SEMI 项由 W2 在真实环境覆盖，不做设备/网络全矩阵。handoff 记录坐标、版本、实际音频输出/状态和结果，仅必要时附截图或短录屏。收到 ready/ended 不能代替听见声音；无法确认输出则保留待验。

**失败恢复**：先区分验证环境与产品/永久内容问题。已有有效证据不因工具故障作废；无可用环境时记录待验并交所有者，不搭新平台或反复创建浏览器 profile。单 URI 暂不可达只有限重试该项，不扩大为全站 UI 验收。

**定向验证**：复用 R2–R4 已通过的一致性结果；仅对缺证据或受影响的 M7–M13 做现有入口小样本或直接 SEMI 实测。相关实现、依赖、输入与环境未变不重跑单元测试；无全仓 build/Forge，无主网铸造，无重传。

**完成证据**：handoff 的播放小节记录 C1/C2 SHA/revision、真实坐标、媒体/Decoder 版本、所选断言及复用来源或实测结果；可注明“由 W2 直接覆盖”。本地入口或永久 Decoder 通过不等于 SEMI wallet_verified，不能只外跳就宣称钱包支持。

**自动下一步**：W2 条件齐则继续；条件缺失直接 W3，handoff 使用 `status=external_pending`，在 `localCodeReady/completedSteps` 保留已通过事实。待总控收到外部输入后恢复 W2，不把整条线无限挂起。

## 2. 集成验收矩阵

下表保留全部 17 项安全/功能断言，作为**按影响选取的目录，不是每次执行完整矩阵的门槛**。结果统一记 handoff：所选编号、覆盖范围、`pass/fail/external_pending/not_applicable`、理由、证据来源、revision 及相关 SEMI 版本；沿用证据注明其适用条件，不生成独立 `acceptance-matrix.md`。未选择本轮重测不等于 not_applicable 或新一次 pass；没有有效证据则保留未验证/待办。

- 清单/导出变化：选择 M1/M2/M14/M15 及受影响的 M3/M4/M6/M17；35 首映射与 70 项留存结果保留完整本地核对，不追加全量网络读回。
- 媒体或播放接入变化：按受影响类型选择 M7–M13；不默认整段试听、故障全排列或跨设备矩阵。
- 首次宣称 SEMI 已支持某 collection/网络：其实际发现、标准/数量、当前持有及钱包内播放必须有真实证据；按适用项选 M2–M11/M14/M16，不拿本地页面或外跳替代。后续只对受影响能力补验。
- 权限/消息来源等安全断言被本次改动影响时不得跳过；证据有效时复用，不以“减轻验证”降低安全完成标准。

| 编号 | 操作与实际断言 | 本地阶段 | SEMI 阶段 |
|---|---|---|---|
| M1 | 曲目页每个已部署坐标都在 inventory 中；同一 schemaVersion/revision；ready 排除原因可追溯 | 全量自动 | 导入包 revision 与应用配置一致 |
| M2 | OP 与 ETH 同号 Token、同地址合约也按 chain 分离；测试链不混入生产 | 全量自动 | 钱包切链后无串资产 |
| M3 | ERC-1155 的 uri 展开正确，35 首映射齐；balance 为 0 不显示持有，数量大于 1 不强行显示 1 | 复用资产证据/真实快照 | 刷新样例余额与索引，钱包数量一致 |
| M4 | ERC-721 当前 owner 与索引一致；Echo origin/sourceScore 仅作来源 | 复用规则/真实快照，不冒充当前持有 | 刷新样例 owner 与索引；已转让作品不得仍列为原持有人当前资产 |
| M5 | collection 导入覆盖后续新 Token，不能只有样例白名单；分页不漏项 | 查接口/已存在样例 | 用已有多页或新增真实证据核验；无样例明确待验，不为测试擅自交易 |
| M6 | metadata 缺字段、URI 空/未定稿、坏图片、媒体读取失败均明确显示，未完成 Score 不冒充可播放 | 静态/真实失败状态 | 钱包不白屏、不误报成功，有重试/永久入口 |
| M7 | Material 的 audio MIME 路径实际可听、暂停/恢复、自然结束；seek 仅在支持时展示 | 复用或现有入口小样本，结束受影响才补测 | SEMI 内实际音频输出；仅外跳不通过 |
| M8 | Score 永久版本：首播手势、ready/state/ended/error、时长单位正确 | 复用或现有 HTML 按影响补测 | 钱包容器和迷你条状态一致 |
| M9 | Echo 永久配方播放保持 recipe/manifest，不换成第 36 首母带或 Score 底曲 | 复用或真实 Echo 小样本，连续性受影响才补测 | 钱包容器内可听；无消息桥不展示假控件 |
| M10 | 切曲/跨详情切换只留一个声源，停止/关闭无残留声音；后台行为如实反映实际状态 | 复用或在现有入口定向验证 | 同一 SEMI 实例内验证 |
| M11 | 父子窗口来源和 schema 校验、旧帧消息无效、未知命令无效、ready 前命令不伪成功 | 复用已有消息证据；缺项交实际容器验收 | 实际 WebView/iframe 策略通过 |
| M12 | 网站/API/CDN 不可用时，真实 tokenURI/永久 metadata 能导向实际可播放内容 | 复用永久资源/断站证据；有缺项才局部验证 | 钱包不硬依赖项目登录/官网可达 |
| M13 | 单网关失败/全部失败有界处理；公共网关临时失败不伪称永久资产丢失或自动重传 | 复用或仅受影响故障路径 | 实际网络错误能恢复或明确报错 |
| M14 | 接入资料无 JWT、手机号、私钥、用户行为追踪；只包含必要公开资产资料 | 静态检查 | 钱包到播放器不传账户秘密 |
| M15 | revision 更新可检测，原已铸 NFT 仍用原永久引用；新包不能悄悄改旧作品 | 差异校验 | 明确缓存更新/导入版本后按受影响项复验 |
| M16 | 链上铸造/收藏者实际接收地址，与 SEMI 当前展示钱包及余额一致 | 使用已授权既有回执 | 用户实际钱包可见且能播放；缺账号/签名明确待验 |
| M17 | 两链 35 首归档对应 70 个 trackId × chainId 结果；已完成项具接收者/数量/事件证据 | 复用 P17/历史及批量交易证据，全量本地映射核对；缺项才读链 | 钱包接入结果与留存状态分别记录，不要求 70 笔交易 |

SEMI 社区身份登录与链上地址登录均不改变 NFT 标准。由不同登录入口收藏时，分别核对实际接收地址；不得假设外部钱包地址自动属于某个 SEMI 账号，更不能把登录成功当作资产接入成功。

## W2 — 有权限后完成 SEMI 内真实验收

**输入依赖**：P13-R4 在本次验收资产范围内 package_ready、W0/W1 的协议与影响项清单、明确外部执行授权、SEMI 当前可测版本、可用测试账号及已持有真实资产。无需先完成重复本地播放验收；未部署网络另记待办，不阻断已具备条件的子集。当前计划不替代授权与真实输入。

**实际文件/符号**：`P13_HANDOFF` 中的钱包验收小节，必要附件才放 `P13_EVIDENCE`；合作方实际实现路径由其提供后登记。历史参考路径 `getOwnedNFTs()`、NFT owned/holders 接口仅作映射线索，不直接修改。

**具体操作**：

1. 核对实际 SEMI build/version、支持网络和接入包 revision，确认它支持标准、数量、audio/HTML 两类 media 与必要播放控制。若导入格式不同，P13 可在自己的 exporter 中增加派生格式，不手写地址、不改共享合同。
2. 将可发送的资料整理好；只有明确允许外部联系或外部写入后才发送/提交。无权限时输出接入说明和待执行动作给用户/总控，不创建 PR、不操作 SEMI 后台。
3. 按本次接入/变更影响选择 M1–M17 的钱包侧断言，复用 P13-R3 的有效链/资源证据，不要求每次整矩阵。验收时刷新样例的当前 owner/余额和索引状态，不能用旧归档回执证明今天仍持有。真实账号与签名由持有人提供；使用已有资产，不为凑测试擅自转账、铸造、导入私钥或迁移账户。
4. 资产发现失败时分开定位：未启用网络、合约未导入、索引延迟/分页、ERC 标准或数量、metadata、媒体容器。记录最小可复现坐标/响应，交给对应所有者；本地网站能播不能替代钱包能播。
5. 首次宣称某 production collection/网络已支持时，至少有一个该范围真实代表的资产展示和钱包内播放证据；同资源音频可复用，但实际钱包的网络发现/容器接入不能只靠外跳或本地网站推断。后续未受影响的有效结果直接引用，原曲 35 首资料由自动一致性检查覆盖，不逐首试听。
6. 钱包发布/导入由 SEMI 负责；版本变化只重测受影响能力，不重复全站测试。应用发布版本、registry revision 与证据覆盖不一致时先核对实际差异；相同资产/资源和未变能力可复用，确有未覆盖变化时才将相应项保持 external_pending。

**失败恢复**：缺权限/账号/网络支持，只阻断该外部路径，保留完整对接包。SEMI 代码需改时出具体适配任务及验收条件，由合作方或另行授权任务执行；不能在 reference 目录修后宣称已完成。
