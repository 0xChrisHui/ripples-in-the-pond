## 3. 统一状态词

| 状态 | 含义 |
|---|---|
| `passed` | 该项要求对应的代码/真实环境已验收并附证据 |
| `code_ready` | 本地实现与相关检查通过，外部链/钱包/发布尚未完成 |
| `needs_visual_acceptance` | 可运行候选已交付，运动范围、排版或文案等待用户早上目验 |
| `external_pending` | 缺外部权限、素材/手记、签名、预算或对方动作，明确列出具体受影响部分 |
| `failed` | 有可重现失败及保留的现场，不能按完成交付 |

手记未提供不妨碍曲目馆其余功能验收；需标记内容状态。SEMI 对接包可单独 `passed`，SEMI 实际钱包体验若无证据保持 `external_pending`。

## 4. 最小充分验证

- 文档和文案纯变更检查 diff、链接、定向文本；逻辑变更检查相关类型/lint/测试。
- 布局、焦点、GL运动与退场时序在 K2 同一次必要浏览器会话检查；各线不另跑整套。单独执行一条线时用它自己的必要会话，不要求先做四线总控。
- P17 合约/幂等/权限涉及资产安全，执行完整对应安全 Gate、测试网证据和链上对账；与UI验证区分。
- K2 在单一集成环境补必要的交叉验证：旧导航删除后新曲目入口、Score/原曲/Echo互斥、退场与36圆恢复、同revision地址一致。
- 上表是断言清单，不是每次改动必须重跑的矩阵；只选择本次影响项。相关源码/依赖/配置/环境未变的结果可复用，无关 commit 不使其失效；动态链状态在相关真实操作前刷新。
- P17 产出一次原曲/永久资源证明，P13 复用，只验导出一致性和真实 SEMI 接入差异；不重复下载 35 首或再做 70 项相同链读取。新的交易/变化项仍逐项对账。
- 不设50次采样、10遍完整播放或固定时长观察。普通修复少量对照足够即停；统计/长时问题才按理由扩测。普通结果写已有 handoff，不另建每Step报告。
- 只有路由/打包/生产运行时风险才集中 build 一次，不把需要构建推导为需要整套 verify.sh；合约安全检查与 UI 验收互不绑定。
- 无业务代码改动的本次 playbook 编写，只跑文档静态检查，不运行上述应用与链验证。

## 5. 发布与回退

本地验收不自动触发发布。用户另行要求上线时，总控核对最新主线与明确发布范围。UI可按已验证最终状态单批发布；包含合约/数据库/永久资源的范围执行对应完整Gate。

UI回退按本轮集成提交回退；已发生的链上交易和永久上传保留凭证并停止后续写入，不能描述成可用git撤销。任何待核验交易标记 unknown，先查链/账本。
