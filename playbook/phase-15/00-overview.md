# Phase 15 — 全站丝滑体验与永久播放可靠性（Overview）

> **立项日期**：2026-09-05
> **状态**：详细 playbook 已建立，尚未进入性能代码施工
> **取代范围**：取代旧 P15“音效系统扩展”；旧项退回未排期清单，不挤占 P16
> **覆盖页面**：`/`、`/me`、`/score/[id]`、`/artist`、登录入口，以及完成后的 P14 页面

---

## 1. 三句话概念简报

1. “丝滑”不是把等待换成更漂亮的 loading，而是让点击立即响应、真实内容尽早出现，并让较慢的数据和重型效果在后台渐进完成。
2. 性能优化必须区分冷启动、站内二次进入、数据等待、音频启动和播放中掉帧；不同问题不能用同一个缓存或动画掩盖。
3. 网站/CDN 可以提供高速路径，但链上 tokenURI、Arweave metadata、永久音频和 Decoder 仍是可脱离本站复现的唯一真相。

---

## 2. 产品目标

让用户进入任何核心页面时都立即看到稳定、可理解的界面，并尽快使用真实数据；首页水塘和音乐圆圈不再被整批网络请求拖住，`/me` 不再因身份恢复或某一栏目变慢而整页等待，NFT 播放不再因 Arweave 多资源下载与集中解码造成长时间无反馈。

```text
用户点击路由
   ↓ ≤100ms 有视觉反馈
稳定页面外壳立即出现
   ├─ 真实缓存可用 → 先显示并后台刷新
   ├─ 无缓存 → 各内容区独立渐进加载
   └─ WebGL / 音频 / 非首屏资源按优先级启动

播放永久 NFT
   ↓
链上 / Arweave manifest = 唯一真相
   ├─ 网站在线：高速镜像优先
   └─ 镜像失败或网站关闭：Arweave + 永久 Decoder 复现
```

---

## 3. 已冻结原则

### D1 — 感知速度和完整速度分别验收

- 路由点击后必须立即给反馈，不能等接口返回后才切画面。
- 页面外壳、主标题和首要操作先出现；次要数据、图片、WebGL 和音频可以渐进补齐。
- 渐进展示必须保持位置稳定，不能用“先快后整体跳动”换取假速度。

### D2 — 只用真实数据加速

- 允许使用按用户或数据版本隔离的最后成功缓存，不使用 mock、虚构数量或临时音乐圆圈。
- 缓存命中后采用 stale-while-revalidate：先显示真实旧值，再后台刷新。
- 私人数据必须绑定用户身份；登录切换、退出或 schema 不兼容时立即丢弃，绝不串档。

### D3 — 永久真相与高速镜像分层

- NFT 永久内容仍由链上 tokenURI 与 Arweave 恢复，高速镜像不能成为唯一播放来源。
- 网站在线时可按 Arweave txid/content hash 命中 CDN 或对象存储镜像；失败后回退现有双网关。
- 不采用“每次播放都由 Next.js API 临时代理整段音频”的常态路径，避免额外网络跳数与服务端带宽单点。
- 现有 NFT metadata 不可改；加速能力必须兼容其原始永久 manifest。

### D4 — 先测量再改代码

- 每个 Track 必须先记录基线、再实施、最后用相同环境复测。
- 报告同时保留 p50/p95、冷/热两态和失败样本，不用一次最快截图宣称完成。
- 若卡顿发生在音频已全部进入内存之后，必须转查主线程、WebGL、GC 和调度，不把问题误归因给 CDN。

### D5 — 复用现有能力

- 复用 P8/P9 的 AutoDpr、WebGL fallback、页面级会话清理和 reduced-motion。
- 复用 P11 的分区失败边界、Score 永久 manifest 与独立播放会话。
- 复用现有 Edge/CDP、Lighthouse、`scripts/verify.sh` 和 Foundry 验证链；不为统计面板先装新依赖。

### D6 — 架构修改单独过门

- 本 playbook 只冻结目标和施工顺序，不在立项时修改 `docs/ARCHITECTURE.md`。
- 进入 CDN/对象存储、高速资源解析器、全局缓存合同等架构施工前，必须先取得用户明确授权并同步架构文档。
- 任何新服务或依赖先按 `docs/STACK.md` 报批。

## 4. 初始体验预算

以下是 P15-0 的初始验收目标；基线完成后只能凭真实设备证据调整，并记录用户拍板。

| 用户时刻 | 初始目标 |
|---|---|
| 点击站内入口 → 看见反馈 | p95 ≤ 100ms |
| 热导航 → 稳定页面外壳 | p95 ≤ 300ms |
| 冷启动 → 稳定页面外壳 | p95 ≤ 1.0s |
| 首页热进入 → 第一批真实音乐圆圈 | p95 ≤ 800ms |
| 首页冷进入 → 第一批真实音乐圆圈 | p95 ≤ 2.5s |
| `/me` 热进入 → 已缓存档案可见 | p95 ≤ 700ms |
| `/me` 在线刷新 | 不阻塞缓存内容，单区失败不拖累其他区 |
| NFT 热播放 → 听到声音 | p95 ≤ 500ms |
| NFT冷播放走高速路径 → 听到声音 | p95 ≤ 2.0s |
| 布局稳定 | 核心页面 CLS ≤ 0.1，无整区突然位移 |
| 动态流畅度 | 桌面健康设备目标 55–60 FPS；移动端低于预算自动降级 |

测量至少覆盖 10 次冷启动和 10 次热进入；桌面与移动视口分别记录，不把开发态 HMR 数据混入生产构建结论。

## 6. 明确不做

- 不用假数据、固定假数量或占位圆圈制造“秒开”。
- 不为了分数删除用户已确认的水塘视觉、P9 动画或永久凭证。
- 不在未测量前重写整个首页、`/me` 或 Score 播放器。
- 不把私人 `/me` 数据放进公共 CDN 或跨用户共享缓存。
- 不把本站后端变成所有音频请求的永久代理。
- 不修改历史 NFT metadata、tokenURI 或已经冻结的永久输入。
- 不承诺断网播放；目标是“本站关闭后仍可从链上与 Arweave复现”。
- 不在本 Phase 扩充音效数量；原 P15 音效扩展已退回未排期清单。
- 不顺带实施 P16 原生钱包、多链或 Ethereum Mainnet。

## 7. 完成标准

- 四个核心路由和 P14 页面（若届时已上线）都有冷/热、桌面/移动、登录/未登录的可重复基线与完成证据。
- 首页页面外壳立即可见，第一批真实音乐圆圈在预算内出现，GL/音频预热不与首屏关键资源抢带宽。
- `/me` 不再被单一身份或栏目请求整页阻塞；真实缓存先显示、在线数据独立刷新、换号绝不串档。
- Score/P14 播放具有高速镜像 → Arweave 双网关的有界降级，且永久 Decoder 在屏蔽本站域名后仍可复现。
- 生产构建路由切换无白屏、无明显布局跳动；交互延迟和动态帧率达到冻结预算或按证据取得用户豁免。
- 完整 `scripts/verify.sh`、production build、浏览器矩阵与故障演练全绿；每项结论都有 review/evidence，不以主观“感觉快了”替代。
