# P15-E — API、查询与缓存一致性合同

> **目标**：减少页面等待中的真实服务端成本，并给公共数据、私人数据和永久 NFT 资源建立不同的缓存规则。
> **原则**：缓存是加速副本，不是第二套含糊真相。

---

## 1. 数据分级

| 等级 | 示例 | 允许缓存 | 失效依据 |
|---|---|---|---|
| 公共稳定 | tracks、公开 artist 内容 | CDN/服务端/客户端真实快照 | 数据版本、更新时间、显式 revalidate |
| 私人可变 | `/me` 唱片、录音、素材 | 仅 owner 隔离的浏览器缓存与短期服务端响应 | userId、authSource、schemaVersion、mutation |
| 永久内容 | NFT metadata、events、sounds、P14 clips | 按 txid/hash 永久缓存 | 内容寻址；字节不一致即错误 |
| 链上当前态 | ownerOf、队列/交易状态 | 短 TTL 或事件驱动刷新 | block/event、状态终态 |
| 认证秘密 | access token、私钥 | 不进入页面数据缓存 | 只按现有安全模块管理 |

---

## 2. Server-Timing 与请求预算

- 核心 API 分段记录 auth、DB、RPC、Arweave、序列化和总耗时。
- 日志只记录阶段与匿名请求 ID，不记录 token、私钥或完整私人响应。
- 每个页面记录请求数、传输字节、重复请求和瀑布依赖。
- 相同页面一次进入内，完全相同的公共/永久请求必须去重；私人请求按 owner 和 token generation 隔离。

---

## 3. 查询与响应瘦身

- 先删除首屏不消费的字段和重复链上读取，再决定是否增加索引或聚合 API。
- 列表接口返回稳定 ID、更新时间和最小首屏字段；详情按用户动作再取。
- 数据库索引只针对真实慢查询计划建立，migration 单独给用户执行，不在代码失败后临时追加。
- API 任一字段失败时，若产品允许局部容错就返回明确 partial 状态；不能因统计附属字段让主内容 500。

---

## 4. stale-while-revalidate 行为

- 命中有效真实缓存：立即显示，并在后台发起一次去重刷新。
- 在线返回更新：按稳定 ID 增量合并，保持滚动位置与视觉锚点。
- 在线失败：保留缓存并标记“暂未刷新”，不冒充刚刚更新。
- schemaVersion 不兼容、owner 不符或关键字段损坏：丢弃该缓存，进入诚实 loading/error。
- mutation 成功：只失效受影响实体/栏目，不清空全站缓存。

---

## 5. 高速媒体镜像生命周期

- ingest 时从 Arweave 读取一次并校验 txid/hash，再写静态对象。
- 镜像键由永久 txid 或内容 hash 决定，不能由可变文件名覆盖。
- 缺失对象可以按受控后台任务回填；用户播放请求不负责同步搬运大文件。
- 记录命中率、回退率、字节量和错误率；不记录钱包与音频偏好的可识别组合。
- 服务商、域名、额度与清理策略在 D 架构 Gate 统一拍板。

---

## 6. 步骤

1. E0：为核心 API 加分段计时并形成请求/体积表。
2. E1：公共 tracks/artist 缓存合同与请求去重。
3. E2：`/me` owner 隔离缓存和 mutation 失效合同。
4. E3：链上当前态与终态队列刷新策略。
5. E4：永久资源 txid/hash 镜像索引与回填设计。
6. E5：慢查询、坏缓存、旧 schema、换号和并发刷新测试。

---

## 7. 完成标准

- 每个核心 API 的慢点可从 Server-Timing 定位，页面不存在无意义串行瀑布。
- 公共、私人、永久和链上当前态没有共用错误缓存策略。
- 换号、logout、token 失效、旧 schema 与 mutation 后刷新均无串档或长期陈旧。
- 永久资源镜像可删除后重建，删除镜像不影响 tokenURI 与 Decoder。
- 响应体积、请求数和 p95 有前后证据，完整验证通过。

---

## 8. 必停条件

- 需要新增数据库索引/schema、外部缓存服务或付费套餐。
- 缓存优化要求改变现有鉴权、NFT 永久真值或用户数据可见范围。
- 想引入 Service Worker、全局状态库或请求缓存依赖；必须先报告复杂度和退出方案。
