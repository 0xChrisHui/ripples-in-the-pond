# P15-0 — 全站性能基线与体验预算

> **目标**：建立所有后续优化共用的测量真相，并由用户冻结优先级与预算。
> **本 Track 不优化业务代码，不修改视觉方向，不接入新服务。**

---

## 1. 为什么先做基线

同一句“卡顿”可能分别指路由没有反馈、身份恢复过慢、接口等待、WebGL 首帧慢、音频下载慢、集中解码卡住或播放时掉帧。若没有同环境前后对照，很容易优化了错误层，甚至只是把等待移动到另一个页面状态。

---

## 2. 必测页面与状态

| 页面 | 冷启动 | 热导航 | 特殊状态 |
|---|---|---|---|
| `/` | 清缓存首次进入 | 从 `/me`、`/artist` 返回 | WebGL healthy/fallback、音乐圆圈接口慢/失败 |
| `/me` | Privy 与 Semi 各一次 | 已登录回访 | 未登录、换号、三接口分别慢/失败、有本地草稿 |
| `/score/1` | 永久资源无缓存 | 已访问后二次播放 | CDN候选关闭、单/双 Arweave 网关失败、reduced-motion |
| `/artist` | 字体/图片冷缓存 | 站内热导航 | stats API 慢/部分失败 |
| P14 页面 | P14 完成后纳入 | 已缓存 recipe/碎片 | 重复碎片、单碎片失败、本站域名屏蔽 |

测试使用 production build；每种主场景至少 10 次，保留 p50、p95 和最慢样本瀑布。

---

## 3. 统一时间点

- `navigationIntent`：用户点击或键盘激活入口。
- `routeFeedback`：旧页面首次出现离场/按下反馈或新 loading 外壳。
- `shellVisible`：新页面主结构、标题和首要操作稳定出现。
- `realContentVisible`：第一批真实数据可识别并可交互。
- `fullPrimaryReady`：当前页面首要任务完整可用；不等待页尾与低优先资源。
- `glHealthy`：首页 PondGL 报告 healthy 或明确进入 fallback。
- `firstCirclesVisible`：第一批真实音乐圆圈稳定出现。
- `audioIntent` / `firstSound`：用户点击播放与首个可听样本。

所有时间点写入统一的 performance mark；日志不得包含访问令牌、邮箱、完整钱包之外的私人档案内容。

---

## 4. 当前代码假设（必须用证据证实）

1. `/me` 的 `identityPending` 会在 Privy/Semi 身份未恢复或 owner 尚未对齐时隐藏三段档案，即使部分本地真实数据已经存在。
2. `/me` 三个服务端请求虽已并行，但录音分支会在初次读取中逐个上传本地草稿，再次拉取后才 resolved，可能拉长该分区等待。
3. 首页 `/` 直接复用客户端 `/test3`，`Suspense fallback={null}`，曲目请求、球体模拟与异步 PondGL 之间缺少可测的稳定首帧合同。
4. 首页在球体建立后以 6 worker 预热当前组音频，可能与首屏图片、字体或 GL chunk 争用带宽。
5. Score 播放器在 ready 前下载底曲、events、sounds map 和全部已用音效，点击播放后再集中 decode，可能造成首播长等待。
6. 根布局同时预加载多套字体，可能影响冷启动关键请求；是否削减必须由瀑布证据决定。

这些是审计起点，不是提前裁决。每条必须标记“证实 / 否定 / 影响可忽略”。

## 5. 交付物

- `reviews/<date>-phase-15-performance-baseline.md`：环境、版本、10轮数据、瀑布和瓶颈排序。
- `reviews/evidence/p15-baseline/`：HAR/trace、截图、performance marks 与可复跑命令。
- 一张按“用户影响 × 出现频率 × 修复风险”排序的清单，只把前 1–2 个瓶颈放入下一 Track。
- 初始体验预算的保留/调整表；任何放宽都写理由，不因当前实现慢而自动降低目标。

---

## 6. Stop 0

基线完成后停下给用户看四件事：最慢页面、最慢环节、热进入体验和首个建议施工点。用户确认优先级与预算后才进入 P15-A；基线阶段不顺手修代码。

---

## 7. 验证

- 同一 production commit、同一网络配置和同一设备档位可复跑。
- 冷/热缓存清理方式写清，登录态不依赖手工猜测。
- performance marks 与浏览器 trace 的误差在可解释范围内。
- `scripts/verify.sh` 通过；新增测量代码不得进入永久 NFT 数据或改变页面行为。
