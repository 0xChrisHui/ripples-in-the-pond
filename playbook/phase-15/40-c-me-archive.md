# P15-C — `/me` 私人音乐档案秒开与后台刷新

> **目标**：进入 `/me` 后立即看到档案结构；身份、唱片、录音和素材各自恢复，任何一条慢链路都不能挡住整页。
> **安全红线**：快不能以跨账号缓存、提前显示错误用户数据或弱化鉴权为代价。

---

## 1. 当前真实基线

- 页面已有唱片、录音、素材三段独立 slice 和局部错误边界。
- 三个服务端请求在取得 access token 后通过 `Promise.all` 并行，不应重复“优化”为并行。
- 当前只有素材有按 owner 隔离的本地缓存；唱片没有同等级快照，录音只立即合并本地草稿。
- `identityPending` 在 auth 未 ready 或 archive owner 未对齐时隐藏所有档案段。
- 录音加载会读取服务端记录，再逐个上传本地草稿，必要时二次拉取；写操作混入首屏读路径可能放大等待。

---

## 2. 目标状态

```text
进入 /me
  ├─ 立即：档案 Header + 三段稳定结构
  ├─ 身份可安全恢复：读取该 owner 的最后成功真实快照
  ├─ 每段独立后台刷新
  ├─ 本地草稿立即显示为本地状态
  └─ 草稿上传进入后台同步，不阻塞录音列表首次 resolved
```

身份尚未确认时只显示结构和身份检查状态，不读取或闪现任何上一账号的私人内容。

---

## 3. 缓存合同

- key 至少包含 `authSource + userId + schemaVersion + section`，不能只按浏览器或钱包尾号。
- 只缓存渲染首屏所需的最小字段；事件正文、访问令牌和敏感认证信息不得写入缓存。
- 每段记录 `savedAt`、schemaVersion 和完整性校验；过期值可以快显，但必须明确进入 refreshing。
- logout、身份切换、JWT 失效或 owner 不一致时立即清理对应内存状态；磁盘缓存按现有隐私决策处理。
- 在线刷新失败时保留最后成功数据并显示该段错误，不能把真实缓存清成空档案。

---

## 4. 身份与数据解耦

- 页面外壳不等待 Privy SDK；Semi 已有 JWT 时沿用现有快速恢复。
- access token 只获取一次并共享给本轮三段请求；身份 generation 改变时取消旧响应写回。
- archive owner 在开始加载时即可绑定已确认 userId，不要求三段全部 resolved 才显示页面。
- 任何优化不得绕过 API 鉴权，也不得把私人 API 改成公共缓存。

---

## 5. 草稿同步解耦

- 本地草稿先以真实“仅在此设备”状态显示。
- 服务端录音列表第一次返回即可让 recordings slice resolved。
- 草稿上传在后台逐条进入显式同步状态；成功后增量合并，失败保留本地草稿与重试入口。
- 页面重复进入、多个标签页和网络重连不能重复上传同一草稿；沿用现有保存幂等身份或先补齐它。

---

## 6. API 与查询审计

- 分别记录 `/api/me/score-nfts`、`/api/me/scores?light=1`、`/api/me/nfts` 的鉴权、DB、链上补充和序列化耗时。
- 若慢点来自某一查询或字段，先瘦身/加索引；只有三个端点固定重复成本明显时才评估聚合 summary API。
- 唱片轮询在首屏稳定后启动，不与首轮数据争抢；页面无 pending 状态时不轮询。

---

## 7. 步骤与 Gate

1. C0：Privy/Semi、冷/热、三接口独立慢的基线。
2. C1：稳定外壳与 owner generation 合同。
3. C2：唱片/录音/素材三段版本化真实缓存。
4. C3：草稿上传从首屏读取解耦为后台同步。
5. C4：按 Server-Timing 修最慢 API/查询。
6. C5：换号、退出、token 失效、多标签和缓存损坏矩阵。

---

## 8. 完成标准

- `/me` 热进入在预算内显示正确 owner 的真实缓存；无缓存时也立即显示稳定三段结构。
- 三段各自 ready/refresh/error，任一接口慢 8 秒不阻塞另两段。
- 本地草稿不再延迟录音列表首次展示，后台上传状态真实且可恢复。
- Privy↔Semi、账号A↔账号B、logout→back 均无一帧串档。
- API p95 和响应体积有前后证据；`scripts/verify.sh` 与四视口浏览器矩阵通过。

---

## 9. 必停条件

- 需要改变 `/me = 我铸造的` 的产品语义。
- 缓存范围涉及事件正文、认证令牌或跨设备同步。
- 发现慢点必须通过新 DB 索引/schema 解决；按项目规则先报告 migration 范围。
