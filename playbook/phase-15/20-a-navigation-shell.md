# P15-A — 全局导航与稳定页面外壳

> **目标**：任何核心站内入口点击后立即有反馈，新路由先显示稳定外壳，不出现空白或整页等待。
> **前置**：P15-0 已冻结时间点和预算。

---

## 1. 施工范围

- 首页、`/me`、`/score/[id]`、`/artist` 与登录入口的 Link/导航行为。
- App Router 的 `loading.tsx`、Suspense 边界、动态 chunk 与共享 Providers 挂载边界。
- 根字体、全局 CSS 和共享首包的加载顺序审计。
- 高频下一页面的有界预取；不得为了预取抢占当前页面关键资源。

---

## 2. 核心合同

### A1 — 点击反馈不依赖新页面返回

- pointer、键盘和触摸激活后 100ms 内出现按下/离场/进度反馈。
- 反馈不得锁死浏览器后退、复制链接或打开新标签。
- 重复点击同一路由不能叠加多个 loading 或重复请求。

### A2 — 每条路由都有非空外壳

- 页面外壳包含真实页面角色、标题位置和稳定版面高度。
- loading 不伪造 Token、档案数量、艺术家事实或音乐圆圈。
- 错误与无数据是独立状态，不能永久停留在 skeleton。

### A3 — 共享 Provider 不反复重建

- 登录、全局播放器和必要的全局状态只在共同布局边界挂载一次。
- 路由专属 AudioContext、P9、WebGL 与监听器仍在离开时销毁，不能为了“保活”跨页面串场。

### A4 — 预取服从当前页面

- 只预取用户高概率进入且体积可控的页面壳与数据。
- WebGL、完整音频和私人接口不在无用户意图时全量预取。
- `save-data`、低速网络或页面后台状态下停止低优先预取。

---

## 3. 字体与首包审计

- 对根布局每套字体记录请求体积、阻塞关系与实际页面使用范围。
- 只有首屏立即可见且跨核心页复用的字重允许 preload；其余延后或按路由加载。
- 不因追求分数擅自替换用户确认的字体；若需要删减或换字形，作为视觉 Gate 交用户目验。
- 检查 `/` 从 `/test3` 复用是否把 TunePanel、诊断工具或沙盒代码带入生产首包；以构建 chunk 证据裁决。

---

## 4. 步骤

1. A0：记录四核心路由的点击到 feedback/shell 基线与共享 chunk。
2. A1：补齐统一导航反馈和重复导航保护。
3. A2：逐路由建立真实、稳定、可访问的 loading/error 外壳。
4. A3：按 trace 调整 Suspense、dynamic import 和 Providers 边界。
5. A4：为最高频入口加入受网络/可见性约束的预取。
6. A5：复测冷/热导航、后退/前进、换路由时音频与 WebGL 清理。

---

## 5. 完成标准

- 四条核心路由热导航的 feedback 和 shell 达到冻结预算。
- 任一路由数据慢 8 秒时，用户仍能立即识别当前页面、返回或重试。
- 无空白 Suspense fallback、无整页布局跳动、无重复 Provider 或路由会话泄漏。
- 预取不会让首页第一批圆圈或正在播放的音频变慢。
- `scripts/verify.sh`、production 路由往返和键盘/触摸导航矩阵通过。

---

## 6. 必停条件

- 优化需要改变已确认字体、导航信息架构或页面视觉角色。
- 需要新增路由缓存框架、Service Worker 或不在白名单的依赖。
- 为保持页面“活着”必须跨路由共享 Score/P14 的可变播放会话。
