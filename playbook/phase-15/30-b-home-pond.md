# P15-B — 首页水塘、音乐圆圈与首屏优先级

> **目标**：首页先稳定出现水塘与第一批真实音乐圆圈，再渐进启动 WebGL细节、音频预热和低优先效果。
> **红线**：不回退 P8/P9 视觉，不用假圆圈，不让快速层和真实 GL 层发生可见跳位。

---

## 1. 当前链路

`/` 直接复用客户端 `/test3`：曲目数据到达后建立 d3/GL 节点，PondGL 通过 `dynamic(..., ssr:false)` 异步加载；节点 ready 后还会并发预热当前组音频。P15-B 要重排优先级，而不是复制第二套首页。

---

## 2. 首屏分层

```text
Layer 0：黑色/水塘基础背景 + Header（无需曲目、无需 WebGL）
Layer 1：最后成功的真实曲目清单 → 稳定圆圈身份/位置
Layer 2：在线曲目刷新 → 仅增量替换变化数据
Layer 3：PondGL healthy → 无跳位接管真实圆圈
Layer 4：用户意图或浏览器 idle → 当前组音频预热、次要视觉
```

- Layer 1 缓存必须带数据版本、写入时间与来源；无有效缓存时显示诚实外壳，不造假圆圈。
- 快显层和 GL 层共享同一节点 ID、分组和确定性初始坐标，切换时不整体重排。
- WebGL 失败继续使用现有 fallback，页面导航和音乐入口仍可用。

---

## 3. 数据与缓存候选

- 优先审计 `/api/tracks` 当前 5 分钟重验证是否真正进入首屏响应；客户端 mount 后再 fetch 可能浪费服务端缓存优势。
- 比较三条实现：服务端把真实 tracks 传入、路由预取写入共享资源缓存、版本化 last-known-good 客户端快照。
- 只选择测量后最小的一条；不得同时保留三套数据源造成僵化。
- 在线响应为空、schema 错误或版本倒退时，不覆盖最后成功快照。

---

## 4. 网络与主线程优先级

- 第一优先：HTML/CSS、Header、真实曲目清单和可用的首批圆圈。
- 第二优先：当前视口需要的 GL chunk、最小纹理/封面与交互层。
- 第三优先：用户最可能播放的少量音频头部；不能默认 6 worker 与关键资源竞争。
- 最后：非当前组音频、调参工具、诊断 UI 和不可见装饰。
- 切路由、切组、页面隐藏或 `save-data` 时取消未使用预热。

---

## 5. GL 与动态预算

- 保留 AutoDpr、context fallback、reduced-motion 和页面隐藏暂停。
- 分别测量数据 ready、节点建立、Canvas mount、shader 首帧和 2 秒稳定帧率。
- 长任务若来自 d3 初始化、shader 编译或大量 React 节点，按 trace 拆分；不凭猜测关闭效果。
- 降级只减少分辨率、次要装饰和高频输入，不改变音乐圆圈身份、播放和首页导航。

---

## 6. 步骤

1. B0：记录首页冷/热瀑布和 `firstCirclesVisible/glHealthy`。
2. B1：建立真实曲目快显合同与缓存失效规则。
3. B2：建立稳定首帧和 GL 无跳位接管。
4. B3：按优先级重排音频预热、dynamic chunk 与装饰启动。
5. B4：验证切组、播放、返回首页、fallback、reduced-motion 和移动降级。

---

## 7. 完成标准

- 首屏外壳和第一批真实圆圈达到冷/热预算。
- 圆圈从快显到 GL 接管时，ID、标签与位置连续，无整塘闪烁或重排。
- tracks API 慢/失败时仍有诚实、可恢复的页面；有效真实缓存不会被坏响应覆盖。
- 音频预热不会拖慢 GL 首帧或抢占当前播放；离页后无残余下载和模拟。
- 生产构建在桌面/移动、healthy/fallback、冷/热四组矩阵通过。

---

## 8. 必停条件

- 快显方案需要另一套独立球体视觉或修改 P8/P9 已冻结审美。
- 真实数据无法提供稳定 ID/版本，必须先改 API 或 schema。
- 为达到数字必须删除用户可感知的核心水塘效果。
