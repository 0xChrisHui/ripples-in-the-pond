# Phase 14 v2 — 钱包配方音乐 NFT 自动空投（Overview）

> **方案冻结日期**：2026-09-05
> **状态**：核心规则与详细施工蓝图已冻结，尚未进入代码施工
> **取代范围**：完整取代旧 P14“用户手动选音轨 → 合成 MP3 → 主动铸造 RemixNFT”方案
> **网络**：Optimism Mainnet（chainId 10）

---

## 1. 三句话概念简报

1. 钱包地址不是一串直接拿来找音频的字符，而是一枚稳定的音乐种子：同一钱包永远得到同一份配方，不同钱包呈现近似随机分布。
2. 新 NFT 不保存一份重复合成的 MP3，而是永久保存 36 位播放配方和实际用到的 Arweave 音频地址，由播放器按顺序重建约 4 分钟作品。
3. 空投资格只在钱包一生中第一次成功铸造 ScoreNFT 时产生一次；NFT 可以转让，但转走不会重置原钱包的资格。

---

## 2. 产品目标

当一个从未铸造过 ScoreNFT 的钱包，在 P14 上线后第一次成功铸造 ScoreNFT，系统自动为该钱包生成一张专属配方音乐 NFT，并异步空投到该钱包。用户无需选择音轨、制作草稿、合成文件或再次点击铸造；收到 NFT 后，可从首页入口进入播放器聆听。

```text
钱包首次成功铸造 ScoreNFT
        ↓
确认“历史上从未铸造过”且“尚未生成 P14 NFT”
        ↓
钱包地址 → 确定性随机算法 → 36 位 A-Z/0-9 配方
        ↓
生成包含配方和所用 Arweave 地址的永久 metadata
        ↓
运营钱包异步铸造并空投 P14 NFT
        ↓
持有人从首页入口进入永久配方播放器
```

## 3. 已冻结决策

### D1 — 身份与触发条件

- 唯一身份是 OP Mainnet 上的 EVM 钱包地址，不按登录账号、邮箱或设备计数。
- 触发事件是该钱包**历史上第一次成功铸造 ScoreNFT**，不是第一次访问、第一次登录或第一次播放。
- 只有首次 ScoreNFT mint 发生在 P14 正式启用之后的钱包才有资格。
- P14 上线前已经成功铸造过 ScoreNFT 的钱包不补发；它以后再次铸造也不触发。
- ScoreNFT 首次 mint 成功但 P14 上传或空投暂时失败时，系统继续重试同一任务，不把故障误判成第二次资格。

### D2 — 一钱包终身一枚，可转让

- 每个 origin wallet 终身最多生成一枚 P14 NFT。
- P14 NFT 允许按标准 ERC-721 转让。
- 转让后，原钱包仍永久保持“已生成”，不能再次触发或补领。
- 唯一性必须由数据库幂等键和新合约的 origin wallet 约束双重保护，不能只靠前端隐藏按钮。

### D3 — 36 位确定性随机配方

- 固定字符表为 `ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789`，每个字符对应一个约 7 秒音频碎片。
- 配方固定为 36 位，按位顺序播放，总时长约 252 秒；真实时长以对应碎片实际时长之和为准。
- 每一位独立、均匀地落在 36 个字符之一，因此允许重复，也允许某些碎片完全不出现。
- 输入只使用规范化后的 20-byte 钱包地址；不加入 Score tokenId，确保同一钱包的结果永久唯一。
- 算法采用带版本域的 Keccak-256 确定性字节流，并用拒绝采样消除 `% 36` 的取模偏差。
- 配方版本、字符表顺序和公开测试向量必须在主网上线前冻结；以后算法升级不得改变 v1 结果。

### D4 — 永久保存配方，不合成新 MP3

- 36 个源音频碎片先独立上传 Arweave，并冻结字符、交易 ID、内容哈希和精确时长的总清单。
- 每枚 P14 NFT 的 tokenURI 指向独立 Arweave metadata。
- metadata 至少永久保存：配方版本、36 位 recipe、origin wallet、触发它的首枚 Score tokenId，以及 recipe 实际用到的每种碎片对应的直接 `ar://` 地址。
- 重复出现的碎片只需在素材映射中保存一次；播放器根据 recipe 重复引用，完整顺序必须可脱离数据库重建。
- 本 Phase 不生成、不上传新的四分钟 MP3；NFT 的作品本体是“永久配方 + 永久碎片地址”。

### D5 — 独立合约与异步空投

- P14 使用新的 ERC-721 合约，不修改已经部署且不可升级的 ScoreNFT 合约。
- 新合约部署在 OP Mainnet；不部署 Ethereum L1。
- 用户不承担 P14 NFT 的 gas，运营钱包通过现有串行交易与锁机制异步空投。
- ScoreNFT 铸造主流程不能等待 P14 metadata 上传或链上 receipt；P14 故障不得拖垮 ScoreNFT 铸造。
- 同钱包并发、cron 重试和进程重启都必须收敛到同一个配方、同一个资格和最多一次成功 mint。

### D6 — 首页聆听入口

- 首页提供 P14 NFT 的发现入口，让已收到并仍持有 NFT 的钱包进入详情与播放器。
- 播放器从 tokenURI/Arweave metadata 读取 recipe 和碎片地址，按 36 位顺序播放，不依赖数据库保存一份可变副本。
- 音频只在用户点击后创建或恢复 AudioContext，遵守现有 Web Audio 约束。
- Arweave 请求继续使用项目现有双网关 fallback，不硬编码单一网关。

## 4. 永久数据合同

| 数据 | 永久来源 | 作用 |
|---|---|---|
| `recipeVersion` | NFT metadata | 锁定派生算法与播放器解释方式 |
| `recipe` | NFT metadata | 36 位 A-Z/0-9 播放顺序 |
| `originWallet` | 合约 + metadata | 终身唯一资格与作品来源 |
| `sourceScoreTokenId` | metadata | 证明触发资格的首枚 ScoreNFT |
| `clips` | NFT metadata | recipe 中实际出现字符到直接 `ar://` 地址的映射 |
| 源碎片内容哈希/时长 | 冻结清单 + metadata | 校验永久素材没有被替换 |
| 当前持有人 | P14 合约 `ownerOf` | 转让后的所有权，不反向改写 origin wallet |

数据库只负责资格、队列、重试和快速索引；NFT 的 recipe 与播放所需地址必须能在数据库不可用时从链上和 Arweave 独立恢复。

## 5.1 连续执行设计

目标是把临时问题提前暴露、把用户判断集中到少数硬 Gate，使每次获准后的施工批不再中途追问产品细节。

### 开工前一次性准备

1. P14-0 的决策表全部有最终值，不允许代码里出现待定名称、临时文案或假地址。
2. P14-E0 在正式视觉代码前单独共创；用户批准桌面与手机样板、封面方向及五种播放状态。
3. 外部写入分开授权：Arweave 36 段上传、OP Sepolia 部署、OP Mainnet 部署、主网启用分别是四个明确授权面。
4. 每次夜间施工前保存 `git status --short`、环境检查和真实基线；已有脏改动一律保留。

### 必停条件

- `bash scripts/verify.sh` 失败；按项目协议报告原错，不改相邻文件救火。
- 实际改动将超出当前 Step 的 `📦 范围`，或需要修改尚未获批的 `docs/ARCHITECTURE.md` / `docs/STACK.md`。
- 缺密钥、余额不足、两个 Arweave 网关同时不可用、RPC/数据库权限缺失，且有界重试后仍不能取得可靠结果。
- 音频数量、哈希、时长、字符映射与冻结清单不一致。
- 任何主网广播、合约角色变更、启用块写入或生产 cron 开启尚未获得对应 Gate 放行。
- E 的视觉方向、播放衔接或封面形式需要审美判断；不得由执行 AI 猜。

### 不必重新讨论的情况

- 已冻结 schema 内的字段命名、类型修正、测试补齐和现有模块复用。
- 单网关故障但备用网关取回同一字节；receipt 尚未出现但仍在冻结的等待窗口内。
- 幂等冲突准确收敛到既有任务；测试重复触发被合约或数据库按预期拒绝。

> 项目 `AGENTS.md` 仍要求每个可独立验证的小闭环通过后停下并等“继续”。因此详细度可以消除临时决策和返工，但不能把多个 Gate 偷合成一次无人值守主网发布。夜间目标是让获准的单个闭环一次跑完，并留下第二天可直接验收的证据包。

## 6. 明确不做

- 不做用户手动选择音轨的混音台。
- 不做草稿、保存草稿或二次编辑。
- 不合成新的 MP3/WAV 成品。
- 不保证每枚作品都包含全部 36 种碎片。
- 不给 P14 上线前已经铸造 ScoreNFT 的钱包补发。
- 不允许一个 origin wallet 因转让、换登录方式或任务重试获得第二枚。
- 不修改已部署的 ScoreNFT 合约或历史 ScoreNFT metadata。
- 不部署到 Ethereum L1，不扩展多链。
- 旧方案中的 `RemixNFT` 名称、主动铸造流程和“钱包地址 + 唱片 hash”算法均不自动继承。

## 7. Gate 与异常矩阵

| 场景 | 必须结果 |
|---|---|
| 新钱包首次 ScoreNFT mint，发生在启用后 | 创建一条资格并最终空投一枚 P14 NFT |
| 钱包在启用前已有 ScoreNFT | 不补发，后续再 mint 也不触发 |
| 同钱包同时出现两个 Score mint 完成事件 | 只有历史第一枚可建立资格，最多一枚 P14 NFT |
| metadata 上传失败 | ScoreNFT 保持成功；P14 原任务可重试，recipe 不改变 |
| 链上交易失败或 receipt 超时 | 队列保留幂等身份并重试，不能生成第二枚 |
| P14 NFT 已转出 | 新持有人拥有 NFT；origin wallet 仍不能再次触发 |
| 数据库不可用但链上/Arweave正常 | 详情页仍可从 tokenURI 恢复 recipe 和音频地址 |
| 某个 Arweave 网关失败 | 有界切换备用网关；两个都失败时显示可恢复错误 |
| recipe 含重复字符 | 对应碎片按出现次数重复播放，不去重播放顺序 |

## 8. 完成标准

- 36 个源碎片全部具有冻结的 `ar://` 地址、内容哈希与时长记录。
- v1 算法对固定钱包测试向量产生固定 36 位 recipe，跨环境结果一致且无取模偏差。
- 历史资格、并发触发、失败重试、转让后重触发均通过自动测试。
- OP Sepolia 至少完成：首次 ScoreNFT → recipe metadata → P14 NFT 空投 → 转让 → 首页播放的完整闭环。
- OP Mainnet 由用户在部署 Gate 放行后启用，并完成首枚真实空投与永久资源复验。
- 首页入口在桌面和手机均可发现；播放器可完整顺序播放约 4 分钟并正确处理暂停、恢复、结束和网关故障。
- `scripts/verify.sh`、Foundry 测试、production build、浏览器矩阵和主网 smoke 全绿，证据进入独立 review 文件。
