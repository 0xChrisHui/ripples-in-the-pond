# Track C — `/me` 我的音乐档案

> **目标**：把当前后台式列表重新组织为创作者的私人音乐档案；状态更清楚、作品感更强，但不改变登录、录制、铸造或播放能力。

---

## C0｜信息架构确认

### 三个真实集合

| 分区 | 收纳什么 | 主要动作 |
|---|---|---|
| 我的唱片 | 已铸造或正在铸造的 ScoreNFT | 打开作品页、查看状态 |
| 我的录音 | 已保存但未进入铸造队列的录制 | 试听、继续既有流程 |
| 我的共创 | 用户参与或拥有的共创材料 | 进入现有详情或播放行为 |

> 名称可在编码前由用户微调；数据含义不可为配合版式而互换。

### 先确认的真值

1. `/me` 各查询的真实来源、空值和错误形式。
2. 草稿、排队、上传元数据、铸造、设 URI、完成、失败的实际状态枚举。
3. 每张旧卡现有按钮和去向，防止重设计时丢功能。
4. 未登录状态由服务端还是客户端判定；不制造闪烁式假空页。

### 📦 范围

- 只读 `app/me/`、`src/components/me/` 及相关数据源
- `reviews/` 下新增 `/me` 行为清单

### 验收

- 每个旧入口在新信息架构中都有明确归属。
- 所有状态使用项目真实值，无 mock 卡片。
- 得到用户确认后进入 C1。

## C1｜档案页骨架与摘要

### 📦 范围

- `app/me/page.tsx`
- `app/me/loading.tsx`
- `src/components/me/archive/ArchiveHeader.tsx`
- `src/components/me/archive/ArchiveSection.tsx`
- `src/components/me/archive/ArchiveEmpty.tsx`
- `src/components/me/archive/archive.css`

> `archive/` 单层最多 8 个文件；旧组件在替换完成前保留，不并行大删。

### 页面顺序

1. 返回池塘与“我的音乐档案”眉题。
2. 一句私人档案说明，不做 SaaS 仪表盘欢迎语。
3. 三个集合的真实数量摘要。
4. “我的唱片”优先，其次录音与共创。
5. 每节空状态直接说明如何获得第一件内容。

### 视觉

- 唱片使用编号、状态、日期构成书脊式索引。
- 缩略图是辅助，不让每张卡争抢大面积封面。
- 技术状态使用 mono caption；作品名使用 display serif。
- 分区靠留白和细线，不套三层圆角容器。

### 验收

- 未登录、空档案、少量内容、大量内容均不塌陷。
- 首屏能回答“我有哪些唱片、它们现在怎样”。
- 375 px 单列，桌面最多使用适合阅读的两栏，不追求密集网格。
- `bash scripts/verify.sh` 通过。

## C2｜统一唱片与录音条目

### 📦 范围

- 可新增 `src/components/me/archive/ScoreEntry.tsx`
- 可新增 `src/components/me/archive/RecordingEntry.tsx`
- 现有 `src/components/me/NFTCard.tsx`
- 现有 `src/components/me/ScoreCard.tsx`
- 现有 `src/components/me/DraftCard.tsx`
- 对应 section 组件

### Score 条目必须显示

- 作品编号或未完成的录制名称。
- 准确生命周期文案。
- Token ID（仅铸造完成后）。
- 创建时间或最近更新时间（有真值才显示）。
- 唯一主要动作；次要信息不伪装成按钮。

### 状态文案

| 后端阶段 | 用户文案 | 动作 |
|---|---|---|
| 草稿/已录制 | 等待制作唱片 | 进入既有下一步 |
| 队列中 | 已进入压片队列 | 查看进度 |
| 上传中 | 正在保存永久材料 | 查看进度 |
| 铸造中 | 正在写入 OP Mainnet | 查看进度 |
| 设 URI | 正在绑定永久播放页 | 查看进度 |
| 完成 | 永久唱片已完成 | 打开 `/score/<tokenId>` |
| 失败 | 制作没有完成 | 查看真实错误与既有恢复入口 |

实际映射必须以代码枚举为准；表格不是新增数据库状态的授权。

### 播放行为

- 录音试听继续复用 `PlayerProvider`，不另造 audio 元素。
- ScoreNFT 主动作打开 Decoder-first 页面，不在档案卡内再嵌播放器。
- 页面离开时遵守既有播放器契约。

### 验收

- 旧卡所有有效操作均有去向。
- 不把失败状态藏在 hover 或颜色里。
- 20+ 条记录下仍能快速扫描，标题和状态不互相挤压。
- `bash scripts/verify.sh` 通过。

## C3｜认证、错误与移动端

### 📦 范围

- `app/me/page.tsx`
- `app/me/loading.tsx`
- `src/components/me/EmptyState.tsx`
- 登录弹窗只在 Track E 修改；本步只调用既有入口

### 场景

1. 未登录：显示为何需要登录与明确按钮，不返回空白/`null`。
2. 登录恢复中：稳定骨架，不短暂显示“没有作品”。
3. 查询失败：保留页面身份，说明未能载入，并给重试出口。
4. 某一集合失败：其他成功集合仍可浏览，错误范围不扩大。
5. 空集合：针对该集合说明下一步，不用通用“暂无数据”。

### 移动端

- 主要动作始终可见，不依赖 hover。
- 卡片点击区与内部按钮不嵌套成无效交互。
- 底部播放器出现时不遮挡最后一条记录。
- 长地址和状态文案不横向滚动。

### Track C 完成条件

- 三类内容、七类生命周期、未登录/加载/空/错误均可辨认。
- 不改变认证、铸造、数据查询和音频核心逻辑。
- 完整验证与浏览器矩阵通过。
- 更新 `STATUS.md` 后停下，等待用户目验再进入 Track D。
