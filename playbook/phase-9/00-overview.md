# Phase 9 — 日食合奏按键动画（45 候选批量制作版）

> **来源**：2026-08-25 用户拍板。本文件取代 P9 早期“先做一个代表家族再扩展”的执行节奏，成为 P9 当前权威 playbook。
> **目标**：先在 `/test3` 一口气实现全部 45 个动画候选，再由用户集中审阅、删改，最后收盘冻结正式按键动画。
> **三段式契约**：Track A = 全部做出；Track B = 用户审阅与修改；Track C = 清理、定稿与冻结。
> **2026-08-26 状态**：Track A 已完成；Track B 的当前施工权威已切到 `01-v2-shared-state-optimization.md`，本文件保留基线、红线和历史映射。

## 0. 本轮特别授权与仍然有效的红线

### 特别授权

用户明确批准以下两项 P9 专属例外：

1. Track A 不执行“一个代表家族做完即停”，而是连续完成 45 个候选后集中验收。
2. Track B 可按用户审阅结果连续批量修改，不要求每个效果单独等待“继续”。

这两项仅改变执行节奏，不降低质量门槛。`verify.sh` 失败、需要新增依赖、碰架构决策、发生破坏性操作或现场代码与本 playbook 冲突时仍必须停下。

### 不变红线

- 旧 10 效保留代码并冻结触发，Track C 前不删除，且不计入 45 个候选。
- 45 个候选只在 `/test3` 沙盒出现；没有用户明确“上线”指令，不替换生产页面。
- 所有效果只在音乐球正在播放、日食存在时触发；其他情况下按键仍正常发声，但不生成脱离场景的视觉。
- 不新增 npm 依赖、第二套 Canvas 或新的后处理管线；继续复用 Three.js/R3F、现有 SVG/Canvas overlay 和高度场。
- 不修改用户保存的参数基线；按键调制进入独立临时状态，余韵结束后必须恢复。
- 禁止各视觉组件自行监听键盘；键盘只经过统一输入事件和统一视觉状态。
- 禁止凭空生成“假花瓣”等与现有对象无来源关系的贴图。新增痕迹必须从日食、真实花瓣、微光、水面、焦散或画面边界产生。

## 1. 当前真实基线

### 输入与声音

- 本地音效：`public/sounds/` 下 33 个 MP3。
- 声音键位：`A–Z + 3–8 + Space`。
- 大小写视觉模式只改变动画候选，不改变音频：例如 `a` 与 `Shift+A` 都播放 A 音效，但触发不同视觉。
- `3–8 + Space` 在 Track A/B 继续正常发声，不占用 45 个动画槽位。

### 当前 P9 原型

| 临时键 | 对应候选 | 用户判断 | Track A 处理 |
|---|---:|---|---|
| A | FX26 黑盘偏心 | 平平 | 重新设计，迁移到正式键 `Z` |
| B | FX28 微光呼吸交换 | 不错 | 保留机制并精修，迁移到 `Shift+B` |
| C | FX30 花瓣缝合与绷断 | 淘汰当前实现 | 删除“凭空两个椭圆”的方案，必须从真实花瓣产生 |
| D | FX32 安静波 | 完全不可见 | 重做为有明确传播边界的静默前线 |
| E | FX41 月影过境 | 惊艳 | 作为全体候选的构图与可见性标杆，迁移到 `Shift+O` |

### 已证实的判断

- E 成功，因为它改变整幅画面的明暗秩序，并保留日食作为最后亮部。
- B 成功，因为它编舞已有微光，并让日食白环与环境发生交换。
- A 平淡，因为只移动黑盘，缺少白环、光晕或环境的后续因果。
- C 失败，因为新增椭圆没有来源，且对称拉伸、反向飞走过于机械。
- D 不可见，因为它只压低已很微弱的水面梯度，没有真正的波前或对比边界。

## 3. 所有效果共享的合奏规则

### 规则一：延迟回声

日食先响应；约 200–400ms 后，微光、花瓣、水面或画面对侧进行一次更弱的回应。回声是环境反馈，不额外占一个动画 ID。

### 规则二：密集演奏稳定化

输入越密集，日食越稳定凝聚，不无限闪亮或反复重新起音。停止演奏后，才通过安静波、月光折叠或其他余韵释放累积能量。

### 统一预算

| 通道 | 上限 | 连击行为 |
|---|---:|---|
| 局部视觉 voice | 8 | 同效果优先复用；超限时让位给更新、更强或更靠近日食的 voice |
| 环境乐句 | 2 | 混合或延长，不从零重播 |
| 全屏重音 | 1 | 同时只允许一个；其余请求进入抬能或等待，不叠屏 |
| 全屏重音冷却 | 最少 4 秒 | 冷却内不重新起音，只允许有限增强或延长 |
| 临时参数 | 独立于基线 | 最长余韵结束后恢复到用户保存值 |

月光、焦散和全局亮度属于乐句级通道；局部水纹、花瓣和微光可以高频响应。

## 4. Track A — 一口气做出全部 45 个候选

### A0：锁定基线与迁移边界

1. 保存当前 `/test3` 静息、单击和连击录像。
2. 确认旧 10 效入口仍冻结，代码可回退。

**A0 产物**：基线录像、映射快照和 45 项状态表。完成后自动进入 A1，不停下审美确认。

### A1：先建立共享编舞骨架

统一状态至少包含：

- `effectId`、普通/大写轮次、音频键、触发时刻、声音家族与强度。
- 日食真实屏幕位置、半径、播放状态和 reduced-motion 状态。
- 局部 voice、环境乐句、全屏重音与全局冷却。
- 临时参数层与用户参数基线的分离、合成和恢复。

建议模块边界：

```text
src/components/pond-gl-test3/p9/
├─ registry/       # 45 项定义、键位和状态
├─ runtime/        # voice、冷却、包络、共享姿态
├─ eclipse/        # 日食本体消费者
├─ environment/    # 微光、花瓣、水面、焦散消费者
├─ global/         # 稀有全屏重音
└─ review/         # /test3 候选编号与审阅辅助 UI
```

每个子目录继续遵守单层不超过 8 个文件；共享热点只由主执行者修改。

### A2：五条制作 Lane

Track A 可派 subagents 并行制作，但每条 lane 只能写自己的模块，不得直接修改统一键盘入口、共享 runtime、`PondGL.tsx` 或 `GlEclipse.tsx`；最终由主执行者接线。

| Lane | 候选 | 数量 | 核心消费者 |

| A1 日食本体 | FX01–08、25–27、35 | 12 | 黑核、白环、光晕、日冕 |
| A2 微光 | FX09–13、28–29、37 | 8 | 已有漂浮微光、白环交换 |
| A3 花瓣 | FX14–19、30–31、39 | 9 | `WaterPetals` 中的真实花瓣与涟漪场 |
| A4 水面与焦散 | FX20–24、32–34 | 8 | 高度场、折射、月光焦散 |
| A5 场景与全屏 | FX36、38、40–45 | 8 | 多系统场力与全屏重音 |

### A3：每个候选的完成定义

一个候选只有同时满足以下条件才算“做出来”：

1. 按正式键位可触发，页面显示正确 FX 编号和名称。
2. 默认 `/test3` 视觉下肉眼可辨，不依赖先把参数滑块拖到极端。
3. 具有完整因果链：`声音 → 场景来源 → 状态变化 → 至少一个环境反馈 → 消散`。
4. 新痕迹能说明“从哪里来”；花瓣类必须选中真实花瓣，孢子必须从白环产生，边缘侵入必须从画面边界进入。
5. 单击结束后恢复静息；同键连击合并/增强/延长，不从零反复重启。
6. 与其他候选和弦式触发时仍可辨认，且不突破统一预算。
7. reduced-motion 下保留状态提示，但去掉大位移、强闪与全屏扫动。

### A4：Track A 批量验收

- 普通 A–Z 顺序扫描一次。
- 大写 A–S 顺序扫描一次。
- 每个候选保存静息、起音、耦合、余韵四个时刻的证据。
- 对每个家族选择至少一个效果做同键 8 次/秒持续 2 秒。
- 做两键交替 6 次/秒持续 4 秒、四键近同时触发和一段真实演奏。
- 记录 FPS、控制台错误、WebGL context loss、最长余韵恢复和移动端降级。

**🛑 停点 A**：45 项全部能在 `/test3` 触发并有证据后，集中交给用户第一次审阅。不得因某些候选“不够好”提前删掉；Track A 的目标是完整铺开选择面。

## 5. Track B — 用户集中审阅、删除与修改

### B1：第一轮快速审阅

用户按 A–Z、Shift+A–S 顺序体验，每个候选只做一个决定：

- **保留**：方向成立，进入精修或直接冻结。
- **微调**：概念成立，只调整幅度、速度、色彩、时序或反馈比例。
- **重做**：概念值得留，但视觉来源或运动关系错误。
- **删除**：不值得继续，占用预算或与其他效果重复。

审阅记录至少包含：FX 编号、键位、名称、判断、用户原话、修改要求。Track B 删除只冻结注册，不立即删代码，保证整轮可反悔。

### B2：第二轮对比审阅

把“保留/微调/重做”候选按五个 Lane 并排比较，重点删除：

- 只改一个小参数、肉眼平平的效果。
- 与已有候选运动关系重复，只是换颜色或换对象的效果。
- 凭空出现、没有场景来源的效果。
- 单击好看但连续演奏失控的效果。
- 只有截图好看、完整动画奇怪或消散不自然的效果。

### B3：批量修改节奏

1. 先处理用户判定“重做”的效果。
2. 再统一处理幅度/色彩/时序类微调。
3. 每批修改后重复单击与压力测试，不因某个效果返工而中断其余已批准候选。
4. 同一效果修改三次仍未成立时，触发止损：默认删除或回到上一版，由用户拍板。

### B4：Track B 完成标准

- 45 项均已有明确状态，没有“未审阅”。
- 所有“重做/微调”项已重新验收。
- 用户确认最终保留数量与映射原则。
- 输出最终保留表、删除表和仍需技术收束的问题表。

**🛑 停点 B**：用户明确说“定稿/收盘/进入 C”后才进入 Track C。

## 6. Track C — 收盘、删码、冻结最终按键动画

### C1：先冻结最终设计

为每个保留效果固定：

- 正式键位与名称。
- 声音家族、运动来源和主要消费者。
- 起音、峰值、余韵、连击和让位规则。
- 桌面、移动端与 reduced-motion 行为。

如果最终候选少于 45，允许留空、复用家族变体或重新映射；不得为了填满键盘保留弱效果。

### C2：删除淘汰实现

- 删除被淘汰候选的组件、shader 分支、uniform、注册项和死样式。
- 删除旧 10 效及其断裂引用；在此之前再次确认最终系统已覆盖需要保留的能力。
- 合并重复包络、重复坐标转换和重复动画循环。
- 清理 Track A/B 的审阅 UI，只保留必要的开发诊断开关。

### C3：最终演奏验收

必须完成并保存证据：

- 每个正式键单击一次，观察完整余韵。
- 同键约 8 次/秒持续 2 秒。
- 两键交替约 6 次/秒持续 4 秒。
- 四键近同时触发。
- 全键扫描与至少一段真实合奏。
- 最长余韵后参数恢复，无控制台错误、context loss 或持续内存增长。
- 桌面与移动端性能达到 P9 开工基线；降级不能改变按键与声音行为。

### C4：文档与状态收口

- 更新 `STATUS.md`、`TASKS.md`、`docs/JOURNAL.md` 和 `docs/LEARNING.md`。
- 输出 P9 最终 review，记录保留/删除数量、正式键位、性能证据和已知限制。
- `bash scripts/verify.sh` 全绿。

### C5：生产上线 gate

Track C 完成不自动部署。只有用户明确说“上线/部署生产”后，才把最终动画从 `/test3` 提升到生产页面并执行生产部署与线上回归。
