## P1：应在收口前修复

### P1-1：“我的唱片”在读取成功时仍显示错误，中英文都受影响

**位置：** `src/components/me/archive/MeArchivePage.tsx:152`；`src/i18n/use-server-text.ts:13`；`src/components/me/archive/ArchiveSection.tsx:42`、`:45`。

正常情况下，`scores.error`、`echoes.error` 都为空，但调用方仍执行：

```tsx
error={serverText([scores.error, echoes.error].filter(Boolean).join('；') || null, t('errors.records')) || null}
```

`serverText(null, fallback)` 在两种语言下都会返回非空的 `fallback`。本次直接隔离执行该函数，结果为：

| 输入 | 实际返回 |
|---|---|
| 中文、无错误 | `唱片档案读取失败` |
| 英文、无错误 | `Couldn't load your records` |

`ArchiveSection` 因而一直判定存在错误，显示“暂无法核实”和重试入口；记录数为零时，正常空态也被 `!error` 条件挡住。

**修复建议：** 调用方先判断是否真的存在错误，再进行翻译。不要直接把公共函数改成“空输入返回空”，因为 SEMI 本地校验等路径确实需要用缺省文案表达已经存在的错误。

### P1-2：部分铸造和钱包提示保存了翻译成品，切换后仍显示旧语言

**位置：**

- `src/components/music-catalog/claim/EthereumMaterialMint.tsx:24`、`:53`、`:67`
- `src/components/music-catalog/claim/MaterialOrderView.tsx:31`、`:48`、`:59`
- `src/components/mint/ReconnectMintWallet.tsx:16`、`:32`、`:37`、`:44`
- `src/components/music-catalog/claim/MaterialNoticeView.tsx:7`

这些状态保存的是 `t(...)` 生成的字符串，而不是 key。例如，中文模式发生钱包拒绝、钱包未就绪或订单读取失败后，再切 EN，提示标题和说明仍然是中文。反向切换也一样。

异步操作还存在同类问题：在中文模式开始请求，等待期间切 EN，原回调仍可能用捕获的中文 `t`、`copy` 写入提示。

`MaterialNoticeView` 仅翻译“技术详情”标签，直接渲染已经保存的 `notice.title`、`notice.hint`，不会重新翻译。

**修复建议：** 状态保存错误类别、原始错误和插值参数，在渲染时按当前语言生成文字；沿用已有 `Msg` 或 SEMI 的 `{ key, server }` 模式。

### P1-3：英文原曲铸造页面的“技术详情”仍直接展示中文报错

**位置：** `src/features/material-catalog/mint/friendly-error.ts:49`、`:52`、`:55`；`src/components/music-catalog/claim/MaterialNoticeView.tsx:9`。

英文模式只阻止了中文原文成为标题，原文仍被保存进 `detail`，并通过 `<pre>` 直接显示。

本次隔离执行 `describeMaterialError(new Error('请先登录'), 英文文案)`，得到：

```text

detail: 请先登录
```

因此，英文用户展开 “Technical details” 就能看到服务器中文报错。此路径违反验收要求“界面不直接显示服务器返回的中文报错”，不能算作展示层已经全部拦截。

**修复建议：** 英文详情使用前端文案、错误码及可核验的 hash/订单号等结构化信息；不要直接输出中文 `error.message`。中文模式可保留现有原文。

### P1-4：旧录音缓存没有翻译 key，英文模式继续显示中文标题

**位置：** `src/components/me/archive/RecordingArchiveRow.tsx:120`；`src/hooks/me/archive-data.ts:19`；`src/hooks/me/archive-cache.ts:10`、`:13`、`:87`；`src/hooks/me/useMeArchive.ts:167`、`:173`。

P19 为新录音增加了可选 `label: Msg`，显示时却保留：

```tsx
const title = recording.label ? msgText(recording.label) : recording.title;
```

旧缓存只有中文 `title`，没有 `label`。缓存版本仍为 `1`，校验也不要求 `label`；读取后直接进入展示列表。

**触发场景：** 用户此前访问过 `/me`，P19 上线后以英文进入，先显示旧缓存。后台请求失败时，类似“1 · 第 2 次录音”的中文标题会继续保留。缓存允许的最长年龄为七天。

**修复建议：** 对旧录音缓存进行读取迁移，或让缺少翻译描述的旧缓存失效；不要把旧中文展示字符串作为英文模式的最终兜底。

## P2：功能边界与可维护性问题

### P2-1：英文词典加载期间点击 CN，不能取消待完成的英文切换

**位置：** `src/components/pond-shell/navigation/LocaleSwitch.tsx:32`；`src/i18n/LocaleProvider.tsx:33`、`:38`。

首次点击 EN 后，要等词典下载完成，当前 `locale` 才会变成 `en`。这段时间点击 CN，会被按钮的判断忽略：

```tsx
if (locale !== option.locale) setLocale(option.locale);
```

由于当前仍是 `zh`，CN 点击不会更新 `requested.current`；英文下载完成后，页面仍切到 EN。因此 provider 的“只认最后一次请求”保护没有覆盖这个入口。

**修复建议：** 允许当前语言按钮取消尚未完成的切换，或显式管理待切换语言。可通过延迟英文词典请求复测。

### P2-2：艺术家英文内容首次下载失败后，切换语言也无法重试

**位置：** `src/i18n/content/use-english-content.ts:9`、`:13`、`:24`、`:26`。

模块级 `pending` 保存了 `Promise.all(...)`。其中任一下载失败后，`pending` 永久保留为 rejected Promise，没有清空。

之后切回 CN 再切 EN，甚至重新挂载调用该 hook 的组件，都只会再次取得同一个失败 Promise；艺术家内容和手记继续回退中文，通常需要整页刷新才能重新尝试。

**修复建议：** 加载失败时清空失败缓存，并提供重试机会；成功结果继续缓存。

### P2-3：切换语言会重建档案详情节点，丢失展开状态

**位置：** `src/components/me/archive/ArchiveSection.tsx:44`、`:59`。

详情节点使用：

```tsx
<details className="archive-section__details" key={detail}>
```

`detail` 包含随语言变化的错误或说明文字。切换语言后 key 改变，React 会替换该 `<details>` 子树，用户刚展开的说明随之关闭。

这不涉及音频或 Canvas 重置，但说明“切换时完全不重建子树、保留界面状态”的表述过宽。

**修复建议：** 使用稳定身份，或移除以文案作为 key 的做法；需要重置展开状态时，应由真实业务状态变化决定。
