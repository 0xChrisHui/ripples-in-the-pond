## C8 — localStorage JWT → httpOnly 评估 ✅（结论：维持现状，理由留档）

**现状**：自签 RS256 JWT（7 天）存 localStorage `ripples_auth_jwt`，请求经 Authorization
header 携带（不进 URL ✓）；已有 jwt_blacklist 撤销机制。风险 = 站内 XSS 可读令牌。

**改造成本**（httpOnly cookie）：登录端点改 Set-Cookie + `authenticateRequest`/middleware
改读 cookie（兼容 Privy 双源）+ useAuth 客户端登录态改 `/api/me` 探活（不能再读 token）
+ 服务端登出端点 + CSRF 面浮现（cookie 自动携带，需 SameSite/CSRF token 配套）
≈ 三层 4-5 文件、1-1.5 天 + 全登录链路回归。

**风险现实评估**：
- XSS 注入面窄：站内无 UGC 富文本（事件数据是受控 JSON 渲染，无用户可控 HTML 路径）；
  现实入口 ≈ npm 供应链投毒
- 被窃 JWT 爆炸半径**不含资金**：7 天窗口内可冒用收藏/存草稿/铸造（铸造免费、NFT 也归
  用户地址而非攻击者）；链上资产无私钥在本系统，动不了钱
- 主网首发用户量小，上线前窗口做三层改造的回归风险 > 收益

**结论**：维持现状（playbook 明示允许"维持现状 + 理由留档"）。
**触发升级条件**：① 引入任何 UGC 富文本 / 第三方脚本注入面 ② P13 Semi 登录正式化改造
登录栈时一并做 ③ 出现有价值的链下资产（如站内余额）。
