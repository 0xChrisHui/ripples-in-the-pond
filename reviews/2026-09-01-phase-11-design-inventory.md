# Phase 11 全局 UI 再设计盘点

> 日期：2026-09-01
> 范围：生产首页外壳、`/me`、`/score/[id]`、`/artist`、登录、全局播放器、加载/错误态、分享视觉
> 证据：当前生产站桌面/390px 手机截图 + 现有页面与组件源码
> 本轮只做盘点，不改 UI，不改变 P8/P9 首页核心视觉与演奏逻辑。

> **2026-09-01 补充决定**：用户要求取消 `/score/[id]` 外层旧详情页包裹小型播放器的结构。NFT 元数据中钉住的 Score Decoder 将直接成为作品页主体；站内原生层只补返回导航、作品身份、合约地址、铸造交易哈希、永久资源与分享。完整实施约束见 `playbook/phase-11/20-b-score-decoder-page.md`。

## 一句话结论

首页已经是一个完整的“夜塘音乐世界”，但其余页面仍停留在早期 MVP 的黑底卡片模板；P11 的核心不是逐页美化，而是建立一套能把“演奏、收藏、作品、艺术家”串成同一个作品世界的界面语言。

推荐方向已收束为 **「夜塘唱片册 / Night Pond Editorial」**：保留首页的深水、微光和留白，把内页做成唱片内页与艺术家档案的结合，而不是常见 Web3 仪表盘。每条实施轨仍设置独立视觉停点，避免一次性改完全站。

## 当前页面各自应该扮演什么角色

| 页面 | 当前呈现 | P11 应有角色 |
|---|---|---|
| `/` | 成熟的互动夜塘与演奏入口 | 世界入口；核心视觉冻结，只优化导航和响应式外壳 |
| `/me` | 三组数据卡片列表 | “我的音乐档案”：唱片、素材、未完成创作及其状态 |
| `/score/[id]` | 外层旧详情 + 内嵌播放页，形成双层页面 | Decoder-first 数字唱片页：永久播放器是主体，站内层承载身份与链上凭证 |
| `/artist` | 4 个统计卡片的项目仪表盘 | 艺术家与长期创作计划的叙事页，统计退居辅助 |

## 必须先解决的 4 项

### 1. 内页与首页视觉断裂

- 首页有水体、球体、漂浮物、层次光和演奏反馈；三个内页统一退化为 `bg-black + white/xx + rounded card`。
- 内页没有继承首页的色温、材质、图形母题、运动节奏或空间层次。
- 结果是从首页进入内页时像跳到了另一个产品。

**再设计目标**：建立 P11 页面外壳、排版层级、色彩 token、边界/材质、按钮与状态规范；内页使用同一套视觉语法，但不复制高成本 WebGL 水塘。

### 2. `/artist` 仍在表达已经失效的产品叙事

- 页面仍显示“下次空投”和“每 36 首曲目发布时触发一轮空投”。
- 项目现行决策是主网不做空投，因此这不只是视觉陈旧，而是用户可见内容与当前产品真值冲突。
- 页面当前把艺术家缩减为发布数、铸造数、参与者三个数字，没有回答“是谁、为什么做 108 首、作品如何生长”。

**再设计目标**：先确认 `/artist` 是“艺术家个人档案”还是“108 首项目进度页”；移除失效空投承诺，再决定需要保留哪些统计与里程碑。

### 3. 手机端缺少统一响应式合同

- 390px 实测中，`/artist` 的英文标题和两列统计卡向右溢出，右列被裁切。
- 首页标题、组别按钮、演奏说明、登录入口均以桌面固定位置和极小字号为主。
- 多处按钮/链接高度明显小于 44px；分享栏和元数据在手机上更像细小文字，而非可触控操作。

**再设计目标**：以 375–390px 为第一画布；统一安全边距、单/双列切换、长标题换行、44px 触控区、底部 safe-area 和横向溢出门禁。

### 4. `/me` 的认证等待态会整页空白

- `ready=false` 且缓存为空时直接 `return null`；生产无登录截图在桌面和手机均只剩背景。
- 即使最终能加载，用户也无法区分“正在确认身份”“页面坏了”“这里没有内容”。
- 未登录态、空收藏、部分接口失败、上传中、铸造中等状态使用了不同的临时样式。

**再设计目标**：把身份初始化、未登录、空内容、局部加载、局部错误、上链等待统一成可理解的状态系统；任何状态都不允许无反馈空白。

## 系统性再设计清单（11 个界面层）

### A. 全局视觉基础

1. **颜色**：当前全站大量硬编码 `black`、`white/xx`、`blue-500`、`emerald`、`red`；需要区分水体背景、纸面/唱片表面、主文字、次文字、功能色和暖色强调。
2. **字体**：`Azeret Mono` 被设为全局正文，英文品牌、中文正文、链上地址没有清晰分工；需要定义品牌字、阅读正文、数据/链上信息三种角色。
3. **间距与版心**：`max-w-md / xl / 2xl` 各页各自决定；需要移动端边距、正文宽度、作品宽度与宽屏留白规则。
4. **形状与材质**：圆角卡片、细边框、玻璃面板目前没有语义；需要明确哪些是“唱片”“档案”“操作层”“状态层”。
5. **运动**：内页缺少进入、播放、状态变化的统一节奏；需沿用首页的缓慢水波感，并完整支持 reduced-motion。

### B. 全局页面外壳与导航

1. 当前没有共享内页页头、面包屑或主导航；每页各写一个返回链接。
2. `/score` 固定返回“我的收藏”，但公开访客可能从分享链接直接进入且未登录。
3. 首页只有登录入口，`/artist`、公共唱片、个人档案的可发现性弱。
4. 需要设计桌面与手机两套导航形态，并明确“回到水塘”是所有内页的稳定出口。

### C. 首页外壳（不重做水塘）

1. 品牌标题在窄屏上的换行/缩放规则。
2. A/B/C 组别选择的可理解命名、触控面积和当前态。
3. “按 A–Z、3–8 或空格演奏”的教学在手机上没有等价入口。
4. 登录后“我的音乐 / 登出”的信息密度与水塘画面争抢注意力。
5. 只允许调整 UI overlay；P8 水体、球体和 P9 按键动画不在 P11 重做范围。

### D. `/me` 我的音乐档案

1. 页面标题“我的收藏”无法覆盖“我的唱片 / 音乐收藏 / 我的创作”三种对象。
2. 三个区块优先级不清，用户最关心的“刚提交、正在上链、可播放”没有集中呈现。
3. 唱片卡、素材卡、草稿卡是三套临时结构，封面、状态、播放和主操作位置不一致。
4. 需要统一状态标签：本地、已保存、待铸造、上链中、已上链、失败可重试。
5. 空状态应该把用户带回水塘开始聆听/创作，而不是只显示两行灰字。
6. 手机端应优先显示作品与状态，链上细节折叠或后置。

### E. `/score/[id]` 数字唱片页

1. 当前外层先重复作品名、事件数和短地址，内部 Decoder 又呈现一套完整唱片视觉，形成明显的“页面里套页面”。
2. 小尺寸 iframe 产生内部滚动条；作品视觉被压进 360px 高窗口，无法成为页面主角。
3. 新结构以 NFT 元数据原始 `animation_url` 对应的 Decoder 为主体，绝不按当前环境重新拼历史作品 URL。
4. 站内原生层只承担 Decoder 不该承担的可变职责：返回池塘、作品身份、生命周期、链上凭证与分享。
5. 合约地址、Token ID、铸造交易哈希和 Arweave 元数据必须准确区分；用户口语中的“合约哈希”在 UI 中应写为“合约地址”。
6. 数据库降级读链时，`ownerOf` 只能称“当前持有人”，不能冒充原始创作者。
7. 页面必须消除内外双滚动和双音源；全局 BottomPlayer 在 Score Decoder 页面暂停并隐藏。

### F. `/artist` 艺术家与项目页

1. 先修正文案真值：移除失效空投承诺。
2. 增加艺术家身份、项目陈述、108 首计划的时间/章节结构；数字只是证据，不是主角。
3. 进度应设计为创作轨迹或章节里程碑，而非通用蓝色 SaaS 进度条。
4. 统计卡改为辅助信息，并解决手机两列溢出。
5. 是否展示最新作品、链上参与者与外部链接，需要在产品语义确认后另定数据范围。

### G. 登录与身份界面

1. 登录框仍是通用 `zinc-950` 圆角 modal，与夜塘世界没有关联。
2. 手机号、验证码、未注册、Semi 暂停和 Privy 邮箱是完整流程，需要统一步骤感与错误反馈。
3. 需补对话框语义、焦点锁定、Esc 关闭、打开后聚焦、手机键盘遮挡处理。
4. “返回”和“关闭”同时存在但语义接近，需要重新定义。

### H. 全局播放器

1. 当前是通用底栏：脉动圆、曲名、收藏、停止；没有继承水塘/唱片视觉。
2. `/score` 自带大播放器，触发后全局底栏再次出现，需定义主播放器与迷你播放器的关系。
3. 手机端需加入 safe-area、长标题截断、44px 控件和更清楚的播放/暂停语义。
4. 播放、收藏、失败和加载状态应与 `/me`、`/score` 共用反馈规范。

### I. 加载、空、错误与 404

1. 现有 loading 骨架分别复制页面旧布局，重设计后需一起更新，避免布局跳变。
2. 全局错误页和 404 仍是通用黑底大字，与项目叙事无关。
3. 重试、回到水塘、查看个人档案等恢复路径需要按错误场景区分。
4. 状态文案不应只靠极低对比灰字表达。

### J. 分享卡、海报与站外第一印象

1. OG 图与海报仍是黑底 + system-ui + 封面并排/居中的通用模板。
2. 它们是多数新访客第一次看到产品的入口，应与新版 `/score` 同步设计。
3. 需要统一品牌字、作品编号、曲名、二维码/链接、封面边界和夜塘材质。

### K. 可访问性与内容规范

1. 根文档 `lang="en"` 与主要中文界面不符。
2. 大量 `text-white/20`、`white/30` 只适合装饰，不适合关键信息和操作。
3. 多个小文字链接、组别按钮、分享按钮未达到移动触控尺寸。
4. 图标字符（`▶`、`⏸`、`✕`、箭头）需统一可读名称、焦点态和键盘行为。
5. 页面标题、按钮动词、NFT/唱片/素材/收藏/创作等名词需要一份一致用词表。

## 建议施工顺序

### P11-0：盘点与边界（本文件，已完成）

- 冻结首页核心视觉与 P9 演奏逻辑。
- 列出所有需再设计的界面层、内容冲突与移动端问题。

### P11-1：方向与基础规范

- 以“夜塘唱片册”为工作方向；`/artist` 暂以 108 项目为主角，艺术家真实内容留待 D0 确认。
- 建立页面外壳、字体角色、颜色/间距/圆角/状态 token、桌面/手机响应式合同。
- 先做静态视觉样张，不接业务改动。

### P11-2：先重做 `/score/[id]`

- 它是公开入口，有真实 `score/1` 可验，登录依赖最少。
- 同步确定播放器、分享和链上凭证的共同语言。

### P11-3：重做 `/me`

- 在已有视觉基础上统一唱片、素材、草稿与完整状态矩阵。
- 同步解决认证等待空白和局部失败反馈。

### P11-4：重做 `/artist`

- 在页面语义拍板后重写叙事、里程碑和统计层级。
- 修复移动端溢出与已失效空投文案。

### P11-5：全局组件与收口

- 登录、全局播放器、404/error/loading、OG/海报与导航统一。
- 做 375 / 390 / 768 / 1440 四档视觉回归、键盘、触控、对比度与 reduced-motion 验收。

## P11 playbook 收束结果

- 视觉工作方向采用“夜塘唱片册”；首页仍是流动夜塘，内页像安静、克制、带水光材质的唱片档案。
- `/score/[id]` 的 Decoder-first 结构已由用户明确决定。
- `/artist` 在 playbook 中暂以“108 首长期项目为主角、艺术家介绍为叙事支撑”编排；真实姓名、简介、宣言和联系信息在 D0 内容门由用户提供或确认，不允许 AI 虚构。
- 完整执行索引：`playbook/phase-11/00-overview.md`。

下一步不是直接写页面，而是先处理 B0：现有架构文档仍规定站内使用 inline `ScorePlayer`。用户明确同意同步架构后，才开始 Decoder-first 实施。
