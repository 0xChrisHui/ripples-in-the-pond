# P15-0 全站性能基线

## 结论

当前线上最慢且影响最大的路径是首页：热缓存外壳 p95 为 1.45s，冷缓存外壳 p95 为 50.28s；10 次冷测中出现一次约 48s 的网络长尾。更关键的是，首页在 8 秒观察窗内始终没有出现可识别的真实音乐圆圈。首个施工点因此冻结为“全局非空外壳与导航反馈”，随后处理“首页真实曲目快显、GL 接管与预热降级”。初始体验预算全部保留，不因当前实现超时而放宽。

## 测量环境与边界

- 时间：2026-09-06（Asia/Shanghai）；原始记录使用 UTC 时间戳。
- 目标：线上 production `https://pond-ripple.xyz`，Vercel Singapore 边缘节点。
- 本地代码锚点：`cfc9e20f1ca8b05a39506a568f2b19b6386cefaa`。线上响应不暴露部署 Git SHA，因此本地锚点不能冒充线上版本。
- 设备：Windows build 26200，AMD Ryzen AI 9 H 365，32GB RAM，Edge 138.0.3351.109，无人工网络限速。
- 热测：同一浏览器会话连续导航，每路由 50 次；冷测：每轮清浏览器 HTTP cache 与 cookies，每路由 10 次。
- 页面：`/`、`/me`、`/artist`、`/score/1`；未登录态。P14 页面尚未存在于该线上版本，待 P14 稳定后补测。
- 自动化通过 CDP 采集 Navigation Timing、Long Task、资源数量与传输量，并轮询真实 DOM 外壳/圆圈。该批 headless 记录未可靠返回 FCP；CLS 只有 `0` 观测值，二者不作为本轮达标证据。
- `/me` 登录恢复、真实设备触摸、iOS Safari、Android Chrome、真实可听首声及失败网关矩阵不在这批桌面无头浏览器数据内，不能据此宣称通过。

## 结果

单位为毫秒；括号内为 `p50 / p95 / 最慢`。

| 路由 | 热外壳 | 冷外壳 | 最长任务 p95 | 冷传输 p50 | 判断 |
|---|---:|---:|---:|---:|---|
| `/` | 621 / 1451 / 2282 | 2758 / 50284 / 50284 | 345 | 17.64MB | 严重超预算；8 秒内无真实圆圈 |
| `/me` | 686 / 853 / 1026 | 1785 / 1785 / 1785 | 334 | 3.07MB | 热、冷均超预算 |
| `/artist` | 601 / 722 / 957 | 380 / 530 / 530 | 284 | 88KB | 冷外壳通过；热导航仍超预算 |
| `/score/1` | 1412 / 2224 / 2538 | 1212 / 1300 / 1300 | 312 | 0–101KB | 外壳超预算；Token 数据/音频另受网关失败影响 |

首页热测每轮约 10.77MB，冷测中位约 17.64MB，并出现 200ms 以上主线程长任务。其他热路由的 transfer size 受同会话缓存影响出现 0，故只代表浏览器复用，并非页面没有资源。

## 六条起始假设裁决

1. `/me` 身份等待隐藏档案：代码审计证实；登录态时序仍需 P14 合入后的浏览器样本。
2. `/me` 本地录音逐个上传再重拉：代码审计证实，是 C Track 的高风险长尾。
3. 首页复用 `/test3` 且空 fallback：证实；线上 8 秒无圆圈与该风险一致。
4. 首页 6 worker 音频预热竞争首屏：代码审计证实；本轮瀑布不能单独量化其占比。
5. Score ready 前全量下载、点击后集中 decode：代码审计证实；永久底曲网关当前失败，无法取得真实首声样本。
6. 根布局预加载多套字体：证实；Modak 不必进入核心首屏预加载，Cormorant 斜体也不应默认预取。

## 瓶颈优先级

| 排名 | 用户影响 | 频率 | 修复风险 | 施工决定 |
|---:|---|---|---|---|
| 1 | 首页可能长时间只有空水塘，且冷启动体积大 | 每次首访/回首页 | 中 | 先建立非空外壳、真实 LKG 快显与确定性圆圈 |
| 2 | 所有核心路由点击后缺少统一即时反馈 | 每次站内导航 | 低 | 同步补统一反馈、loading/error 外壳 |
| 3 | Score 全量下载后再集中解码 | 每次首次播放 | 中高 | 先加真实分段时序与多候选永久资源解析 |
| 4 | `/me` 身份和草稿同步形成整区等待 | 高频登录回访 | 高 | 等 P14 `/me` 稳定后以 owner 隔离缓存与幂等 RPC 修复 |

只把前两项放入紧接的 A/B Track，避免性能施工同时改动全部业务状态机。

## 预算冻结

| 用户时刻 | 目标 | 决定 |
|---|---:|---|
| 点击入口 → 反馈 | p95 ≤ 100ms | 保留 |
| 热导航 → 外壳 | p95 ≤ 300ms | 保留 |
| 冷启动 → 外壳 | p95 ≤ 1.0s | 保留 |
| 首页热/冷 → 第一批真实圆圈 | p95 ≤ 800ms / 2.5s | 保留 |
| `/me` 热缓存可见 | p95 ≤ 700ms | 保留 |
| NFT 热/冷高速首声 | p95 ≤ 500ms / 2.0s | 保留 |
| 布局稳定 | CLS ≤ 0.1 | 保留，待可观察浏览器复测 |
| 动态流畅度 | 桌面 55–60 FPS | 保留，移动端允许自动降级 |
