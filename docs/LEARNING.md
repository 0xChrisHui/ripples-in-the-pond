### Tailwind CSS
- **是什么**：一个 CSS 工具库，让你用类名（如 `text-white bg-black`）直接写样式，不需要自己写 CSS 文件。v4 版本会自动扫描项目文件找出你用了哪些类名。
- **类比**：像一本巨大的样式菜单，你只说菜名（类名），它帮你做出来。但 v4 的"自动扫描"功能像一个太勤快的实习生，会翻遍办公室所有文件夹。
- **第一次出现**：`app/globals.css`（`@import "tailwindcss"`），Phase 0 初始化

---

### Web Audio API
- **是什么**：浏览器内置的音频引擎，可以低延迟地播放、叠加、变调多个音源。核心对象是 `AudioContext`。
- **类比**：一个小型录音棚——`AudioContext` 是调音台，`BufferSource` 是播放器，`GainNode` 是音量旋钮，全部用线（`connect`）连起来最后接到音箱（`destination`）。
- **第一次出现**：`src/spike/useJamAudio.ts`，Phase 2 Step 0

---

### AudioContext 的用户手势要求
- **是什么**：浏览器安全策略要求 AudioContext 必须在用户点击/按键后才能启动（`resume`），不能页面一加载就自动播放声音。
- **类比**：像餐厅里不能自己去厨房拿菜，必须先举手叫服务员（用户手势），服务员才会帮你上菜（播放音频）。
- **第一次出现**：`src/spike/useJamAudio.ts:29`（`getContext` 里的 `resume`），Phase 2 Step 0

---

### useCallback + 闭包陷阱
- **是什么**：React 的 `useCallback` 会缓存函数，但函数内部引用的变量可能是创建时的旧值（闭包）。如果依赖项写错，回调里拿到的是过期数据。
- **类比**：你拍了一张照片（闭包），照片里的东西是拍照那一刻的样子。即使现实已经变了，照片不会自动更新。用 `useRef` 可以绕过这个问题，因为 ref 像一个"实时监控画面"而不是照片。
- **第一次出现**：`src/spike/useJamAudio.ts:46`（`playKick` 改用 `ctxRef.current` 避免闭包问题），Phase 2 Step 0

---

### 异步操作加锁（防抖）
- **是什么**：异步函数（如 fetch）执行期间，用户可能再次触发同一操作。用一个布尔 flag（锁）防止重复执行。
- **类比**：电梯门正在关的时候，按钮会暂时失效，防止门反复开关。
- **第一次出现**：`src/spike/useJamAudio.ts:76`（`bgLoadingRef` 防止快速点击叠加背景音乐），Phase 2 Step 0

---

### 状态机（state machine）
- **是什么**：先定义一个功能会经历哪些状态，以及状态之间允许怎么切换，比如 `idle → loading → success / error`，避免流程半路卡在假成功或脏状态。
- **类比**：像机场值机，乘客不能从“还没安检”直接跳到“已经登机”；每一步都要按顺序通过。
- **第一次出现**：`reviews/2026-04-10-phase-2-cto.md`，Phase 2 CTO review

### 动态路由（Dynamic Route）
- **是什么**：Next.js 用方括号命名文件夹（如 `[tokenId]`），表示这个路径段是一个变量。访问 `/score/2` 时，`tokenId` 自动变成 `2`，一个文件就能服务所有 ScoreNFT。
- **类比**：像酒店房间号，走廊只有一个设计（页面文件），但每间房的号码（tokenId）不同，内容也不同。
- **第一次出现**：`app/score/[tokenId]/page.tsx`，Phase 3 S6

### OG 分享卡（OpenGraph Image）
- **是什么**：当你在微信/Twitter 分享一个链接时，平台会读取页面的 `og:image` 标签，自动生成一张预览卡片。Next.js 的 `opengraph-image.tsx` 可以在服务端用 JSX "画"出这张图。
- **类比**：像书的封面——你把书推荐给朋友时，朋友先看到封面决定要不要翻开。OG 卡片就是链接的"封面"。
- **第一次出现**：`app/score/[tokenId]/opengraph-image.tsx`，Phase 3 S6

### 链上事件同步（Event Sync）
- **是什么**：你的数据库只知道"自己铸造了什么"，但不知道用户在 OpenSea 把 NFT 转给了谁。定期从链上拉 `Transfer` 事件，把所有权变更记录到自己的 DB，让数据库和区块链保持一致。
- **类比**：像银行对账——你自己的账本记了收支，但每月还要和银行流水核对一遍，确保没有漏记的转账。
- **第一次出现**：`app/api/cron/sync-chain-events/route.ts`，Phase 3B

### 幂等同步（system_kv + UNIQUE 约束）
- **是什么**：`system_kv.last_synced_block` 记录"上次扫到第几个区块"，下次从这里继续；`chain_events` 表用 `UNIQUE(tx_hash, log_index)` 保证同一个事件不会被写入两次。两层保险确保 cron 即使重复跑也不会产生脏数据。
- **类比**：像看书时夹书签（last_synced_block = 书签位置），同时笔记本里用标号防止同一段话被抄两次（UNIQUE 约束）。
- **第一次出现**：`supabase/migrations/phase-3/013_system_kv.sql` + `014_chain_events.sql`，Phase 3B

---

### iframe 嵌入
- **是什么**：`<iframe>` 是一个"页面中的页面"，可以加载另一个网址的内容。ScorePlayer 用 iframe 加载 Arweave 上的 Decoder HTML，让播放器代码和主站完全隔离。
- **类比**：像在电视里看另一个频道的节目——电视机（主页面）提供框架，节目内容（decoder）来自别处。
- **第一次出现**：`app/score/[tokenId]/ScorePlayer.tsx`，Phase 3 S6

---

### JWT（JSON Web Token）
- **是什么**：一种"数字签名的身份证"。服务器签发一段带有效期的令牌，客户端每次请求带上它，服务器验证签名就知道"你是谁"，不用每次都查数据库。由 header.payload.signature 三部分用 `.` 拼接。
- **类比**：游乐园的一日手环——入口盖了章就能一天内随便进各个游乐设施，不用每次重新买票。
- **第一次出现**：`src/lib/jwt.ts`，Phase 4 S0

---

### RS256（非对称签名算法）
- **是什么**：用私钥签名、公钥验证的 JWT 签名方式。私钥只有服务器有（永远不暴露），公钥可以公开。比对称签名（HS256）更安全——即使公钥泄露，攻击者也无法伪造签名。
- **类比**：邮局的蜡封印章——只有你有印章能盖，但任何人都能看出封印是不是你的。
- **第一次出现**：`scripts/generate-jwt-keys.ts` + `src/lib/jwt.ts`，Phase 4 S0

---

### jti + 黑名单（JWT 撤销机制）
- **是什么**：JWT 天生是"签了就生效，到期才失效"的（无状态）。要支持提前作废（如用户登出），给每个 JWT 一个唯一 ID（jti = JWT ID），登出时把 jti 写入 `jwt_blacklist` 表，验证时额外查一次。
- **类比**：信用卡挂失名单——卡片本身没过期，但银行系统里标了"此卡已注销"，刷卡时会被拒绝。
- **第一次出现**：`src/lib/jwt.ts` 的 `revokeJwt()` + `supabase/migrations/phase-4/015_jwt_blacklist.sql`，Phase 4 S0

---

### auth_identities（多源身份表）
- **是什么**：一个中间表，记录"这个用户通过哪种方式登录过"。`users` 表只代表站内用户，`auth_identities` 表记录 `provider`（privy / semi）和 `provider_user_id` 的对应关系，一个 user 可以有多条。
- **类比**：一个人可以有身份证、护照、驾照——都指向同一个人，但发证机关不同。`auth_identities` 就是"证件列表"。
- **第一次出现**：`supabase/migrations/phase-4/016_auth_identities.sql`，Phase 4 S1

---

### 统一认证中间件（authenticateRequest）
- **是什么**：一个共享函数，所有需要登录的 API 都调它来验证"你是谁"。先尝试 Privy 验证，失败再尝试自签 JWT。这样 Privy 用户和 Semi 用户都能通过同一个入口验证身份。
- **类比**：机场安检有两条通道（国内/国际），但最终都汇到同一个候机厅。中间件就是"安检口"，不管你从哪条通道来，验完身份都能进。
- **第一次出现**：`src/lib/auth/middleware.ts`，Phase 4 S1

---

### Token 交换（一次性中转模式）
- **是什么**：用户从外部服务（Semi）拿到的登录凭证（auth_token），到我们后端换成自签 JWT。之后所有请求只认我们自己的 JWT，不再依赖外部服务。这样即使 Semi 暂时挂了，已登录用户也不受影响。
- **类比**：用外国驾照换本地驾照——换的时候需要外国驾照原件，但换完之后在本地开车只看本地驾照。
- **第一次出现**：`app/api/auth/community/route.ts`，Phase 4 S2

---

### Authorization Header vs URL 参数

- **是什么**：HTTP 标准的身份验证方式，密钥放在请求头（header）里而不是 URL 里
- **类比**：URL 参数像把密码写在信封外面（会被路上的人看到），header 像封在信封里面
- **为什么重要**：URL 会出现在服务器日志、浏览器历史、CDN 缓存里，密钥容易泄露
- **第一次出现**：`src/lib/auth/cron-auth.ts`，Phase 5 S0
- **跳过了复述**

### Durable Lease（队列持久租约）

- **是什么**：队列任务被某个 cron 抢到后，在数据库里写入“我正在处理，到某个时间前别人别碰”的锁，而不是只靠 SQL 执行瞬间的锁。
- **类比**：图书馆借书卡。你把书借走后，系统记录到期日；不是管理员看见你拿起书的那一秒才算占用。
- **为什么重要**：链上交易这种外部副作用不能被两个 cron 同时处理，否则可能重复 mint、抢 nonce 或产生孤儿 NFT。
- **第一次出现**：`reviews/2026-04-25-phase-1-4-strict-cto-review.md`，Phase 1-4 回看。

### Sync Cursor（同步游标）

- **是什么**：后台同步链上事件时，用一个数字记录“我已经同步到第几个区块”。下一次从这里继续。
- **类比**：读书夹书签。只有这一页真的读完了，书签才能往后移；如果中间跳过一页，后面很难知道漏了什么。
- **为什么重要**：如果单条事件写库失败但 cursor 仍推进，系统以后不会再回头扫那个区块，空投和 owner 展示会永久建立在错误数据上。
- **第一次出现**：`app/api/cron/sync-chain-events/route.ts`，Phase 3B；在 Phase 1-4 回看中被标为新增 P1 风险。

---

### 分布式互斥锁（SETNX + Lua 安全释放）

- **是什么**：多个进程/服务都可能同时跑同一段代码（比如三个 cron 都想用同一个钱包发交易），用一个共享的 Redis key 来"占座"：`SET key value NX EX 30` — 如果 key 不存在就写入并设 30 秒过期；存在就拒绝。释放时用 Lua 脚本"先 GET 比对再 DEL"，避免误删别人后续抢到的锁。
- **类比**：会议室门口的"使用中"牌子。挂牌前先看一眼有没有别人挂着；自己用完撕牌前再确认一下是自己的牌子（不是隔壁同事换上去的），避免把别人的"使用中"撕了。
- **为什么重要**：运营钱包是一个 EOA，nonce 是单调递增的。两个 cron 同时发 tx 会 nonce 冲突 → 后发的可能 replace 前一笔、被 RPC 拒绝、互相覆盖 → 出现"链上 mint 了但 DB 没记 / DB 记了但链上没成功"的诡异状态。锁是主网前必装的护栏。
- **第一次出现**：`src/lib/chain/operator-lock.ts`，Phase 6 A0；包装 `app/api/cron/process-{mint-queue,score-queue,airdrop}/route.ts` 三个入口。

### Chain ID 单一来源

- **是什么**：把当前链（OP Sepolia 或 OP Mainnet）的 chainId、viem chain 对象、浏览器链接统一放在一个配置文件里，其他代码只引用它，不再各自写死。
- **类比**：像全公司只认一张最新版地图；如果每个人抽屉里都有旧地图，搬家时一定有人走错地方。
- **第一次出现**：`src/lib/chain/chain-config.ts`，Phase 7 A1。

### 按需加载（Lazy Fetch）

- **是什么**：页面首屏只请求必要的小数据，用户真的点击某个功能时再请求大数据。
- **类比**：像餐厅先给菜单，不会把所有菜一次端上桌；你点哪道菜，厨房再做哪道。

### 慢网反馈（Loading Feedback）

- **是什么**：数据还没回来时，先显示 spinner、提示文案和重试按钮，让用户知道页面没有卡死。
- **类比**：像外卖 App 显示“骑手正在路上”和“联系骑手”，比空白页面更让人安心。

### PinInput（分离式验证码输入）

- **是什么**：把 6 位验证码拆成 6 个小输入框，但内部仍合成一个字符串提交给后端。
- **类比**：像快递柜取件码，每个格子只放一位数字；用户看着清楚，系统最后还是读完整 6 位码。
- **第一次出现**：`src/components/auth/PinInput.tsx`，Phase 7 Track D D2。

### Attempted Window（防双发时间戳窗口）

- **是什么**：cron 发链上交易前，先在 DB 写一个 `*_attempted_at` 时间戳；下一轮 cron 看到这个时间戳在 25 分钟内就跳过本行。事务一旦走到终态再清掉时间戳。
- **类比**：像快递柜门口贴的"已联系骑手，请稍候"小条——即使你掉线了，下一个用户看到条子会等 25 分钟再尝试，不会重复寄出第二件。
- **为什么重要**：链上 tx 没有幂等键（每笔都消耗 nonce），cron 如果被 sigkill / 重启 / lease 误判，可能对同一 row 发两次 tx → 双 mint / 双 setTokenURI → 钱花了 NFT 状态错乱。Attempted window 兜底 25 分钟比纯靠 lease 更安全（lease 5 分钟内 row 走完 5 步会让 lease 误清）。
- **判错警告**：`attempted_at = null` **不能**反推"代码 bug"。设计是先写时间戳后发 tx，所以 null 只能说"cron 根本没跑过这行"，而不是"跑了但失败"。要区分"代码没跑"和"跑了但 revert"必须看链上 + Vercel env，不能只看 DB。
- **第一次出现**：`supabase/migrations/phase-7/track-a/032_score_queue_state_machine.sql` + `steps-mint.ts` + `steps-set-uri.ts`，Phase 7 A3+A12。

### React Three Fiber (R3F) / WebGL 渲染层

- **是什么**：用 `<Canvas>` 把 three.js（浏览器原生 GPU 绘图 WebGL 的封装）写成 React 组件，逐像素画球和水面，取代 SVG 滤镜。
- **类比**：SVG 像用一套现成印章盖图案（够用但花样固定）；WebGL 像直接给每个像素发指令，想要折射/高光这种"逐像素扭曲"只能走它。
- **第一次出现**：`src/components/pond-gl/PondGL.tsx`，P8-G G3。

### 代码分割（next/dynamic + ssr:false）

- **是什么**：`dynamic(() => import('X'), { ssr: false })` 让 X 及其依赖（这里是 three，~150KB+）单独打成一个"异步 chunk"，只有真正用到的页面在运行时才下载，不进别的页面首屏。
- **类比**：像超市把冷冻品单独放一个柜，只有买冰淇淋的人才去开那个柜门；逛别的区的人完全不受影响（首页 bundle 零增量就是这么来的）。
- **第一次出现**：`app/test1/page.tsx` 挂 PondGL，P8-G G3。

---

### React 错误边界（Error Boundary）

- **是什么**：一个 class 组件，子树渲染抛错时它接住、显示兜底 UI（这里是渲染 null）而不是整页白屏。React 目前只支持 class 形式。
- **类比**：像电路里的保险丝——某个电器短路时只断那一路，不烧掉整间屋子的电。WebGL 不可用时只让 GL 层消失，SVG 全套照常。
- **第一次出现**：`src/components/pond-gl/PondGL.tsx` 的 `GLErrorBoundary`，P8-G G3（CONVENTIONS §4.2"不写 class"的合理例外）。

---

### CSS 几何图标（字体无关控件）

- **是什么**：用 CSS 边框画播放三角形、用方块画停止状态，不把 `▶/■` 字符直接当作最终 UI。
- **类比**：像按统一尺寸裁切路牌，而不是依赖不同浏览器各自手写一个符号；外观不会因字体不同而变形。
- **第一次出现**：`src/score-decoder/index.html` 的唱片中心控制钮，P12 A-1；用户本轮选择直接进入下一步，跳过该文件代码复述。

### 有界重试（Bounded Retry）

- **是什么**：网络瞬时失败后只再尝试固定次数，并在两轮间短暂停顿；成功继续，达到上限就明确失败。
- **类比**：门铃第一次没响，等一下再按一次；第二次仍没人开门就离开，不会站在那里无限狂按。
- **第一次出现**：`src/score-decoder/index.html` 的 `fetchWithFallback`，P12 A-1；用户要求直接进入下一步，跳过该段代码复述。

### 付费脚本的 fail-closed（默认拒绝）

- **是什么**：当脚本缺少足够信息判断操作是否安全时，默认停止并要求显式选择，而不是猜测后继续花钱。
- **类比**：收银机看不清商品数量时先叫店员确认，不会自动按“一整箱”结账。
- **第一次出现**：`scripts/arweave/upload-sounds.ts` 的旧索引 hash 检查与 `--map-only --dry-run`，P12 C2；用户本轮选择跳过该文件代码复述。

### 精准重部署旧版本（Safe Redeploy）

- **是什么**：环境变量必须立即生效、但当前工作分支不能上线时，重建“现有线上 deployment”，而不是部署本地工作区。
- **类比**：给正在营业的旧机器换电池，不把实验室里尚未兼容的新机器搬进店里。
- **第一次出现**：P12 A-1 切 Arweave txid；精准 redeploy 线上 7 月 26 日版本，避免两参数 `mintScore` 提前撞旧合约。

### Arweave 网关传播不同步

- **是什么**：同一笔永久上传可能先在一个网关可读，数分钟后另一个网关才完成索引。
- **类比**：同一份档案已进中央库，但两个分馆的目录更新时间不同；不能因为一个暂时查不到就重复寄一份。
- **第一次出现**：P12 A-1 永久上传；备用网关先 200，主网关约 7 分钟后 200，最终哈希一致。

### NFT 自包含 metadata 快照

- **是什么**：链上 `tokenURI` 指向永久 metadata，而 metadata 再固定 decoder、事件、底曲和音效表；四项合在一起才能复原当时的作品。
- **类比**：唱片封套里同时封存唱针说明、演奏谱、伴奏和乐器清单，未来网站改版也不影响这张唱片。
- **第一次出现**：P12 A-1 `Ripples #26` 真实 smoke，逐层核对链上 tokenURI 与 animation_url 四个永久资源。

### 可逆授权演练

- **是什么**：先用真实 admin 签一笔测试网 grantRole，确认权限生效，再 revoke 临时角色并核对原业务角色未变。
- **类比**：正式开门前用备用钥匙开一次锁，确认能开后把临时门卡注销，不把测试权限留在系统里。
- **第一次出现**：P12 B5，新 admin 在 OP Sepolia 对临时 MINTER_ROLE 完成 grant → 验收 true → revoke → 验收 false。

### Alchemy CLI Admin API

- **是什么**：官方 CLI 通过浏览器设备授权管理 Alchemy 账户，可以创建 App、设置网络白名单、查询用量并直接调用 RPC。
- **类比**：把网页后台变成可审计的命令清单；先 dry-run 看申请表，再正式提交并用 chainId 验收。
- **第一次出现**：P12 主网凭证准备，用 `alchemy app create --networks OPT_MAINNET` 创建生产 App，并实测 chainId 10。

### API key 要按目标端点验收

- **是什么**：同一个 API key 在同一条链上，不同类别的端点可能受不同套餐权限控制。
- **类比**：办公楼门卡进不了机房，不代表也进不了你要去的会议室；应测试真正要用的入口。
- **第一次出现**：Etherscan 免费套餐不开放 OP 普通链数据，但开放源码读取与合约验证相关端点，因此 P12 无需付费升级。

### 免费额度要算“常驻底噪”

- **是什么**：上线前先把 cron、同步器、告警等无人访问也会发生的调用换算成月用量，再给真实用户流量留余量。
- **类比**：先算空房子的冰箱和路由器耗电，剩下的电量才是人住进来后能用的。
- **第一次出现**：C6 把 4 个外部 job 全按每分钟保守估算为 172,800 次/月，仍低于 Vercel 100 万次免费额度的 18%。

### 验收型动画要立即给反馈

- **是什么**：用户主动打开一个视觉开关时，第一轮效果应立即出现，后续再按设定间隔运行。
- **类比**：按门铃后要立刻听到提示音，不能让人等半分钟猜门铃是否坏了。
- **第一次出现**：P8-L `/test3` 偶发颤动验收，开启即触发一次明显三摆，之后严格按间隔重复。

### 真透明要在合成前保留图层

- **是什么**：前景一旦先与不透明背景混进同一张纹理，后续降低 alpha 无法恢复被覆盖的背景；必须先保留背景层和透明前景层，再做最终合成。
- **类比**：把人像和风景先压成一张照片后，擦淡人像不会自动长回背后的风景；需要一开始就保留两张底片。
- **第一次出现**：P8-L 真透明合成 review，把 `/test3` 的背景与 SphereInstances 拆成两个 FBO，并固定预乘 alpha over 契约。

### A/B 对照状态先于渲染实现

- **是什么**：在真正切换渲染管线前，先把“原合成 / 真透明”的选择做成只保存状态的入口；这样可以先验证按钮不会重置球、播放或涟漪。
- **类比**：装修前先装一个不会动家具的双路电闸，确认切换开关安全，再接入新线路。
- **第一次出现**：P8-L A0，默认原合成，`trueAlphaComposite` 只支持控制台选择和 URL 复现，两个选项暂时共用旧路径。

### Renderer 状态必须用 try/finally 恢复

- **是什么**：多 pass 渲染会暂时改 render target、clear 色、viewport、scissor 和 camera layer；每帧结束时必须恢复快照，异常也不能把状态泄漏给 R3F 下一帧。
- **类比**：借用工作台前先记下工具摆放，做完不管成功失败都放回原位，下一位使用者才不会拿错工具。
- **第一次出现**：P8-L A1/A6，`water/composite/render-passes.ts` 统一保存并在 `finally` 恢复 renderer/camera 状态，context restore 后重置并清空 height ping-pong。

### 实验版本要先隔离再维修

- **是什么**：发现视觉版本有严重问题时，先把当前版本复制到独立路由，再让原路由回到上一个可对照版本；这样维修不会破坏回退基线。
- **类比**：先把现状封存成一份实验副本，再修实验副本，原件留在旁边随时比较。
- **第一次出现**：P8-L 真透明合成从 `/test3` 隔离到 `/test4`，开关与圆圈位置/大小问题延后在 `/test4` 维修。

### Render target 尺寸不能再走逻辑像素 viewport

- **是什么**：`useFBO` 的宽高是物理像素；Three.js `renderer.setViewport` 接收的是逻辑像素并会乘 DPR。把 FBO 物理宽高传进去会重复放大。
- **类比**：照片已经按 150% 放大打印，又让打印机按 150% 再放一次，纸张只能留下被裁切的一角。
- **第一次出现**：`/test4` 真透明双 target 在 DPR 1.5 下把球和背景放大裁切，而 DOM 编号仍按 CSS 像素保持原位。

### A/B 开关必须保留到用户明确拍板

- **是什么**：实验方案的验收开关不是临时代码噪音，而是用户比较同一状态下新旧视觉的工具；用户明确拍板后就应删除旧路径，避免长期维护两套行为。
- **类比**：试音时必须保留 A/B 键，只有听众明确选定后才能拆掉另一条线路。
- **第一次出现**：`/test4` 恢复“原合成 / 真透明”两段按钮，默认原合成，并共享球、水位、播放和高度场状态。

### 真透明单路径合并

- **是什么**：背景和球体分别渲染到两个颜色 target，再由合成 shader 统一处理折射和可见度；确认方案后，旧合成代码、flag 和 UI 入口全部移除。
- **类比**：试音结束选定正式母带后，控制台只保留正式线路，避免误把试听线路当成产品功能。
- **第一次出现**：P8-L `/test3` 合并 `/test4` 真透明实现。

### 透明分层需要干湿两套背景语义

- **是什么**：把背景与球拆成两个纹理还不够；水上球透明处应看到无动态水光的干背景，水下球才看到折射、焦散和倒影形成的湿背景。
- **类比**：隔着玻璃看水塘与把玻璃沉进水里是两种光学关系，不能只靠同一张水面照片调整透明度。
- **第一次出现**：P8-L R1 严格分层维修，`water-distort-shaders.ts`。

### 预乘颜色的剩余亮度空间

- **是什么**：预乘 alpha 纹理的 RGB 上限是 alpha；增亮应朝 `vec3(alpha)` 靠近，而不是直接加光导致越界裁白。
- **类比**：杯子只能装到刻度线，补光要倒进剩余容量，不能倒满后继续灌再把溢出的部分切掉。
- **第一次出现**：P8-L R1 球体波纹与月光增亮修复。

### RGBA 颜色不等于图层身份

- **是什么**：多种语义对象一旦合进同一张 RGBA 纹理，最终像素只剩颜色和透明度，无法再可靠判断它来自水上层还是水下层。
- **类比**：两种颜料混进同一个杯子后，只看最终颜色无法把每一滴还原到原来的瓶子。
- **第一次出现**：P8-L R1 用户复验失败，R2 改为逐实例 `aSubmerge` + 水上/水下两张球体纹理。

### 半透明前景最后画仍会透出动态背景

- **是什么**：绘制顺序只能保证谁在上面，不能阻止半透明像素显示下面的内容；若下面的动态纹理不应穿过前景，必须额外保留精确覆盖信息或调整主体不透明度。
- **类比**：把半透明玻璃最后放到水面上，仍然能看到玻璃下面的波纹；“最后放”不等于“不透”。
- **第一次出现**：P8-L R2 放弃仅直绘水上球，增加 `aboveSphereTarget` 并用真实 alpha 控制静态背景揭示。

### 本地短音效需要先压缩再预加载

- **是什么**：页面播放器会在可演奏前并行下载全部音效；短音效使用 MP3 可以显著降低等待时间和移动端流量。
- **本次映射**：`A-Z + 3-8 + Space` 共 33 个键，播放器按键名读取对应的 `/sounds/<key>.mp3`。
- **第一次出现**：P9 音效替换闭环，`src/hooks/useJam.ts`。

### 音效动画先看攻击与频谱，再选形态

- **是什么**：峰值决定视觉能量上限，攻击时间决定“突然击穿”还是“缓慢顶起”，频谱重心决定深层压力、薄膜还是高频碎光。
- **类比**：同样是一滴水，石块落水、雨丝落水和气泡破裂留下的水面证据完全不同，不能只换颜色复用同一圈动画。
- **第一次出现**：P9 `R` 键「深层压力花」，`key-fx/KeyFxLayer.tsx`。

### 部署完成和产品完成是两个状态

- **是什么**：主网部署完成代表链、生产环境和铸造闭环已经可运行；软启动观察和后续视觉/音效开发仍然可以独立进行。
- **本次映射**：P12 部署阶段关闭，保留 7 天 health、cron、双队列和告警观察；开发主线回到 P8-L / P9。

### 动态层次需要少量近静止参照物

- **是什么**：所有物体都明显运动时，眼睛会失去速度参照；保留少量近静止小物体，反而能让其他运动显得更有深度。
- **本次映射**：P8-L 视差幅度拉满时，最小的一组球只保留 2%–10% 视差，其余球继续按确定性种子产生幅度和转角差。
- **第一次出现**：`/test3` 视差去同步验收微调。

### 调参上限不等于当前值

- **是什么**：扩大滑块的最大值只增加可探索范围，不会修改 store 中已经保存的当前参数，也不会让页面刷新后自动变得更激烈。
- **本次映射**：`/test3` 流场强度、尺度、速度上限各扩大 3 倍，默认值与用户当前保存值保持不变。
- **学习记录**：用户直接进入下一项调整，跳过了上一轮 `life-core.ts` 关键逻辑复述。

### 默认值与 localStorage 存档需要分开处理

- **是什么**：修改代码默认值不会覆盖浏览器里已经保存的调参；如果产品要求用户刷新后立即看到新默认，需要只迁移旧默认值，同时保留用户主动保存的其他参数。
- **本次映射**：滚轮步长从旧 `.025/.05/.1/.75` 迁移到 `.075`，其余保存参数不被覆盖。

### 临界阻尼适合做连续的滚轮位移

- **是什么**：直接把当前位置乘一个比例去追目标，会造成“突然开始、突然停下”；临界阻尼用目标距离产生加速度，再用速度阻尼刹车，能在不明显反弹的情况下平滑到达目标。
- **本次映射**：`pointer-fx.ts` 的 `shift` 由速度模型推进，滚轮步长和水位边界仍由原来的 store 控制。

### 速度上限和位移目标是两件事

- **是什么**：限制速度只会让物体更慢地到达目标，不会改变目标位置；这适合解决滚轮连续输入时的冲刺感。
- **本次映射**：`shiftVelocity` 限制为临界阻尼理论峰值的 60%，`shiftTarget` 仍按原来的滚轮步长累计。

### 输入步长和动画速度应该分层

- **是什么**：输入步长决定一次操作把目标推多远；动画速度决定画面多快到达目标。两者混在一起会导致停止输入就停止画面，或不同步长带来不同速度。
- **本次映射**：滚轮只累计 `shiftTarget`，`shift` 由独立的 `0.35 shift/秒` 速度上限和加减速规则推进。

### 多层动画必须共享限速后的运动源

- **是什么**：主物体已经使用平滑速度模型时，附加的滞后、视差或去同步层不能再直接追输入目标；否则附加层会绕过主物体的速度限制，视觉上仍然像“输入即移动”。
- **本次映射**：`life-core.ts` 的每球 `_lagShift` 改为跟随 rate-limited 的 `shift`，保留个体时滞差，但不再直接跟随 `shiftTarget`。

### “默认值”不等于“覆盖已保存值”

- **是什么**：代码默认值只会用于新用户或重置操作；浏览器 localStorage 中已有的用户调参通常优先级更高。
- **本次映射**：滚轮和隐现默认值更新后，`/test3` 需要点击面板“重置”才能立即看到新的一组默认参数。

### 可调参数要进入同一个 store

- **是什么**：如果参数只写死在渲染文件里，用户无法实时比较；把参数放进现有 store 后，面板可以修改、保存、重置，渲染循环也能实时读取。
- **本次映射**：滚轮目标步长、最高速度、启动加速度、停止减速度统一进入 `RippleTuning` 和 `RippleSpikePanel`。

### R3F 图层必须在对象真正挂载时绑定

- **是什么**：只依赖配置值的 effect 可能先于异步创建的 Three.js 对象运行；如果 ref 当时为空且依赖不再变化，layer 永远不会写入。
- **本次映射**：球体看似存在，其实一直画在湿背景 layer 0；改用 callback ref 后，网格挂载当刻进入独立球体 layer，水上/水下 FBO 才真正获得像素。
- **验证方法**：调试视图直接采样两个 render target；红=水下、绿=水上、蓝=RGB 超出 Alpha。不要再用解析圆形或最终截图猜中间通道。
- **第一次出现**：P8-L 真透明 R3 最终维修，`SphereInstances.tsx`。

### 综合 Review 要分开“代码缺陷、流程风险、用户 gate”

- **是什么**：代码缺陷可以由修复进程直接关闭；流程风险需要执行护栏；主观视觉和产品去留必须留给用户拍板，三者不能混成同一个优先级列表。
- **本次映射**：P8 综合审查只把 3 个运行时正确性问题列为 P1，把工作区提交交给独立进程，并保留 R3/L 目验和首页迁移为用户 gate。

### 手工创建的 GPU 资源必须跟随组件释放

- **是什么**：Three.js 的 geometry/material 由手工工厂创建时，React 卸载不会自动回收对应 GPU 资源，所有者必须显式调用 `dispose()`。
- **本次映射**：`QuadScene` 显式持有独占 geometry，`WaterDistort` 清理时统一释放 sim/composite 的 geometry 与 material，不碰 `useFBO` 管理的纹理。
- **第一次出现**：P8-RUN-01，`water-distort-setup.ts` 与 `WaterDistort.tsx`。

### 渲染画面与 DOM 交互层必须共享健康状态

- **是什么**：Canvas 失败后若 DOM 命中层仍按另一套布尔值运行，就会出现“看不见但点得到”的状态分裂。
- **本次映射**：`PondGL` 上报 unavailable/healthy/lost/error，页面再合并 forced；只有 healthy 才挂导航、loading、球命中、日蚀和 pointer 监听。
- **第一次出现**：P8-RUN-02，`PondGL.tsx` 与 `app/test3/page.tsx`。

### 高度场尺寸必须跟随 Canvas 比例

- **是什么**：波纹传播依赖纹理网格；Canvas 宽高比变化但高度场不变时，网格映射会被拉伸，圆波就会变椭圆。
- **本次映射**：保持纵向 256 预算，横向按 Canvas 比例动态计算；resize 同步两张 target、sim/composite `uDelta`、ping-pong 引用与清场标记。
- **第一次出现**：P8-RUN-03，`WaterDistort.tsx` 与 `water-distort-setup.ts`。

### 全局输入监听必须尊重局部 UI 边界

- **是什么**：window 级 wheel 监听会先看到面板滚动事件；若不按事件目标分流，就会同时劫持原生滚动和场景控制。
- **本次映射**：明确 UI 统一标记 `data-pond-ui`，wheel handler 用 `closest()` 提前返回；水塘区域仍使用原深度速度模型。
- **第一次出现**：P8-INT-01，`pointer-fx.ts` 与 `/test3` UI 容器。

### 减少动态效果应停掉自动注入而非全部反馈

- **是什么**：`prefers-reduced-motion` 应冻结随机游走、持续漂移和个体视差等非主动运动；点击、拖拽等用户直接触发的反馈仍可保留。
- **本次映射**：随机漂移停止向 d3 速度注入并借既有阻尼自然停稳，视差幅度与转角平滑回到中性值，重新启用时也不会瞬间跳变。
- **第一次出现**：P8-A11Y-01，`life-core.ts` 与 `gl-sim-waves.ts`。

### 自适应降级组件必须恢复进入时的渲染基准

- **是什么**：临时性能降级不能把修改后的 DPR 留给后续渲染；组件卸载与 context 恢复都要回到挂载时捕获的 Canvas 基准并重置采样状态。
- **本次映射**：AutoDpr 只在 Canvas `[1,2]` 范围内升降，关闭时恢复基准 DPR，重新开启不会把旧低清值误当成新上限。
- **第一次出现**：P8-PERF-01，`auto-dpr.tsx`。
- **复述记录**：用户要求综合 Review 连续修复，本闭环跳过逐文件复述。

### Pointer Capture 的每条终止路径都要释放业务状态

- **是什么**：`pointerup` 不是拖拽唯一终点；系统手势取消、capture 丢失和组件卸载也必须执行同一条幂等清理路径。
- **本次映射**：球命中按钮在 up/cancel/lost/unmount 时统一释放 `fx/fy` 和 simulation 热度，Enter/Space 则复用点击播放逻辑而不进入拖拽。
- **第一次出现**：P8-INT-02，`SphereOverlay.tsx`。
- **复述记录**：用户要求综合 Review 连续修复，本闭环跳过逐文件复述。

### 同名文件不能证明仍有运行职责

- **是什么**：迁移树里的同名组件必须以 import 和真实挂载为准；产品决定已取消的零引用副本会误导后续维护者。
- **本次映射**：test3 已固定水面且明确不挂水位指示器，因此只删除其死副本，保留 test1/test2 的在用实现。
- **第一次出现**：P8-STRUCT-02，`pond-gl-test3/overlay/WaterLevelIndicator.tsx`。

### 规格文档必须标明后来的用户决定覆盖了什么

- **是什么**：保留历史方案没有问题，但过期规则必须明确写出替代日期和当前权威，否则维护者会把正确实现“修回”旧稿。
- **本次映射**：95-L 统一到 `test3-life-v2`、9 开 1 关与 R3 halo-only 契约；K10 标明暗纹方案已被亮底 mix 和五套花纹替代。
- **第一次出现**：P8-DOC-01，Phase 8 的 90-K/95-L/96-L 契约同步。

### 浏览器回归要断言状态转换而不只检查 HTTP 200

- **是什么**：页面能打开不能证明 WebGL 生命周期、交互取消、DPR 恢复或 reduced-motion 正确；必须触发真实状态变化并读取可观察结果。
- **本次映射**：Edge CDP 实测 context lost/restore、pointer capture、键盘 `aria-pressed`、横竖屏 Canvas 尺寸与 DPR `2→1.5→2`。
- **第一次出现**：P8 综合 Review 浏览器回归矩阵。

### 批量做视觉候选也必须共享同一套演奏预算

- **是什么**：一次制作很多候选只是在审美阶段扩大选择面，不代表每个效果可以拥有独立键盘监听、亮度叠加和无限 voice；共享 runtime 才能保证候选组合后仍像同一件乐器。
- **本次映射**：P9 Track A 同时制作 45 效，但统一限制局部 voice、环境乐句与全屏重音，并让连击复用、增强或延长已有状态。
- **第一次出现**：`playbook/phase-9/00-overview.md`。

### 视觉迁移应共享实现并保留显式回退入口

- **是什么**：沙盒目验通过后，正式页若复制一份实现会很快产生视觉分叉；迁移观察期也不应立即删除旧路径。
- **本次映射**：`/` 直接复用 `/test3` 的 GL 体验并按路由隐藏调参工具，`/v1` 作为稳定、可分享的旧 SVG 版本入口。
- **第一次出现**：P8 J 线首页迁移收口。
