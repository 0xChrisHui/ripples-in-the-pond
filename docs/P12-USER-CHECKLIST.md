## 分组一：随时能做，不用等我

### ☐ C6 免费额度盘点（约 20 分钟）

**为什么**：主网上线后流量变真实，得知道哪个服务会先撞免费额度天花板。

**你做**：逐个登录后台，把「已用量 / 上限」截图或抄给我：

| 服务 | 去哪看 |
|---|---|
| Vercel | vercel.com → 项目 → Usage（看 Bandwidth、Function 时长） |
| Supabase | supabase.com → 项目 → Settings → Usage（看 Database size、月活） |
| Upstash | console.upstash.com → 数据库 → 看 Daily commands |
| Alchemy | dashboard.alchemy.com → Apps → 看 Compute Units 用量 |
| cron-job.org | 后台看有没有额度/频率提示 |
| Resend | resend.com → 看每日发信量上限 |

**我做**：汇总成一张「够用 / 要升级 / 要降频」的表，进 review。
**成功标志**：六行结论齐全，没有服务处于"马上撞墙"状态。

## 分组二：需要我在场配合（每件 10-20 分钟）

### ☐ C1 尾巴 — 换 ADMIN_TOKEN + Alchemy key

**为什么**：`ADMIN_TOKEN` 顺手轮换；Alchemy key 在这次调试的输出里露过。

**流程（跟 CRON_SECRET 那次一模一样）**：
1. 我生成新 `ADMIN_TOKEN` → 写你桌面文件 + 剪贴板（**不进聊天**）
2. 你去 Alchemy 后台 → 你的 App → API Key → **Regenerate**（或新建一个 App）→ 复制新的 HTTPS URL
3. 你在 Vercel 改这三个变量：`ADMIN_TOKEN`、`ALCHEMY_RPC_URL`、`NEXT_PUBLIC_ALCHEMY_RPC_URL`
4. **Redeploy（不带 Build Cache）** ← 上次就是这步没跑完，导致验证全反
5. 我验证：新值通、旧值 401、cron 保持全绿

**成功标志**：`/api/health` 200 + cron 10 分钟内正常跑过。

### ☐ C2 换 Turbo 钱包 + 充值（约 15 美元）

**为什么**：Arweave 永久存储的"油钱"。旧钱包是早期临时生成的，主网换新的。

**我先做**：查旧钱包余额 + 查官方文档额度能否迁移 → 生成新钱包 → 把**新地址**给你。
**你做**：
1. 从交易所/钱包转 **ETH**，网络选 **Base**，金额约 **0.005 ETH**
2. ⚠ **转之前把地址和网络截图发我确认**——网络选错币直接消失
**我收尾**：跑充值脚本换成 Turbo credits + 实测一次小上传扣费成功。

**成功标志**：新钱包能成功上传一个测试文件并扣费。

### ☐ C3 运营钱包充主网 ETH（约 150 美元）

**为什么**：主网上每次铸造 NFT 的 gas 由这个钱包代付。

**你做**：往 `0x306D3A445b1fc7a789639fa9115e308a34231633` 转 **≥0.05 ETH**，网络选 **Optimism**。
- 这个地址在所有链通用（就是现在的运营钱包）
- OP 链 gas 极便宜，0.05 ETH 够铸几万次
- ⚠ 同样：**转之前截图发我确认地址+网络**

**我做**：充值到账后复核 `check-balance` 的告警阈值（现在的 0.05 是按测试网拍的）。
**成功标志**：`/api/health` 里 `wallet` 从 `low` 变正常。

### ☐ C5 数据库快照（我做，你只需说一声）

**为什么**：部署日要清空链相关的旧表（B-1 已证明不清就会卡死），清之前必须有可恢复的备份。

**我做**：用管理密钥把所有表导成 JSON 存到本地 `backups/`（仓库外，不进 git），并做一次恢复演练。
**你做**：说一句"跑备份"。部署日前一天我会再跑一次新的。
**成功标志**：备份文件存在 + 恢复演练成功（"没演练过的备份 = 没有备份"）。

## 分组三：需要你的审美/内容决策

### ☐ A-1 解码器 UI 优化轮

**为什么**：解码器 = 买家点开 NFT 时看到的播放器。**这版定稿后，主网铸出的每一枚 NFT 永远用这版**（地址焊死进 NFT，改不了）。

**流程**：
1. 我在浏览器里打开当前版本给你看
2. 你像点评设计稿一样提意见（说人话就行："按钮太小"、"想要水波背景"）
3. 我改 → 你看 → 循环到满意
4. 你点头定稿 → 我做三组参数回归验证 → 上传 Arweave → 切三环境 env

**成功标志**：你说"就这样"，且三组参数（旧格式 / 新音效表 / 无参数 demo）都播放正常。

### ☐ D-1 曲名定稿（**永久，最容易后悔的一项**）

**为什么**：曲名会**永久写进每一枚 NFT** 的名称、描述、属性里。现在有一批曲子叫"16"、"17"这种数字占位名。

**你做**（三选一，可混用）：
- **A** 把正式曲名发我（哪首叫什么），我写 SQL 你在 Supabase 跑
- **B** 告诉我哪几首暂不开放铸造，我在前端拦掉
- **C** 明确接受占位名永久（不推荐）

**成功标志**：开放铸造的曲目全部有正式名，或明确记录了接受占位。

## 分组四：钱包准备（部署日前必须完成）

### ☐ admin 独立钱包（合约的"房产证"）

**为什么**：admin 钱包持有合约治理权。红线是 **admin ≠ 铸造热钱包**（热钱包在服务器上天天用，泄露就等于治理权被接管）。

**我做**：写一次性脚本在你本机生成，私钥写进**仓库外**的本地文件（不进 git / 不进 Vercel / 不进聊天）。
**你做**：
1. 记住那个文件在哪
2. **把私钥另抄一份到安全的地方**（纸上/密码管理器）——丢了 = 合约永久失去治理权
3. 往这个新地址转一点点 OP 链 ETH 当 gas（约 0.005 ETH 够用）

**成功标志**：地址已记进 runbook，钱包里有 gas。

### ☐ B5 admin 签名演练

**为什么**：部署日要用 admin 钱包做一次授权（不做的话 Orchestrator 拿不到铸造权，整条链路瘫痪）。**没演练过就上阵 = 部署日卡死**。

**我做**：在**测试网**上带你走一遍完全相同的授权操作。
**成功标志**：测试网上 admin 钱包成功发出一笔授权交易。

### ☐ deployer 一次性钱包

**为什么**：专门用来部署合约，**用完即销毁**（runbook §4.4）。

**我做**：生成 + 给地址。**你做**：转约 0.01 ETH（OP 链）当部署 gas。
**成功标志**：钱包有 gas，私钥只存在本地一处。
